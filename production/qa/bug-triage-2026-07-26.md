## Systemic Issues Flagged

1. **The Base/CoreBase refactor (this week's main effort) is a half-finished migration.** Commit
   message itself says "need fix class bassEntity" — 3 independent BLOCKING findings (BUG-024,
   BUG-030, BUG-031) all trace back to the same `Assets/Script/Character/Base/` introduction, and
   together they mean `Core.GetCoreComponent<T>()` — the pattern CLAUDE.md calls the *only*
   sibling-discovery mechanism — is currently non-functional for both Player and Entity, even before
   counting the separate CS0592 compile error. **Recommend: this refactor should not have further
   work stacked on it until it compiles and Setup() registration is verified end-to-end in Play Mode.**
2. **6/6 code-review agents this cycle independently found a compile error** in their assigned file
   subset (Base/Core hub, Player/Entity states, Pathfinding, Enemy/spawn, Map/Room, Pooling/Utility).
   That is a much higher hit rate than last cycle's single suspected CS0592. Strongly suggests the
   branch has not been opened in the Unity Editor since these changes landed.
3. **Player damage/death chain (Bug #6) has now failed in two different ways across two cycles** —
   last cycle it threw `NotImplementedException`; this cycle the exception is gone but the health
   field is disconnected from the SO and no death listener exists. Recommend a dedicated story
   with an EditMode test (`TakeDamage_BelowZero_TriggersDeathState`) per test-standards.md, rather
   than another ad-hoc fix.
4. **Enemy AI regression**: `EntityWeaponMelee.SetAbility()` (BUG-032) and `EntityInput`'s FOV/target
   math (BUG-028) both look like an in-progress edit was committed mid-refactor (old working line
   commented out, replacement incomplete) — same pattern as the Base/Core issue. Consider whether
   this week's commits were pushed before local compilation was checked.
