## ⚠️ VERIFY FIRST — possible build break (compile error / lỗi biên dịch)

**Not yet confirmed by an actual Unity compile** (no Unity CLI in this environment — same constraint
noted in every sprint-05 standup). Flagging with high confidence from static read, needs Editor
Console confirmation before anyone budgets time against it:

`Assets/Script/Poolable/PoolMember.cs:9`
```csharp
[SerializeField] public bool isInPool { get; private set; } = false;
```
`SerializeFieldAttribute` targets `Field` only; applying it directly to an auto-implemented property
(no `field:` target specifier) is CS0592 in standard Roslyn C#. If this compiles as written, the
whole `Poolable/` namespace — and anything referencing it (`EnemySpawner.cs`) — fails to build.

**Important context**: the exact same pattern (`[SerializeField] public T X { get; private set; }`)
already exists, unchanged, in 7 other files that predate this sprint and are described in CLAUDE.md
as stable/working: `Core.cs:5`, `WeaponHolder.cs:8`, `PlayerInputHandle.cs:48`, `RoomCell.cs:13-21`
(5 properties), `RoomGeneraterController.cs:14-16`, `DoorController.cs:8`, `MapCell.cs:11-12`. So
either (a) this has been a silent, long-standing build break nobody caught because there is no CI/
Unity CLI check in this workflow, or (b) something in this project's toolchain tolerates it and my
static read is wrong. **Action**: open the project in the Unity Editor, check the Console for CS0592
before the next sprint starts. This is P1 either way — if broken, it blocks everything; if not
broken, close this item and note why for future triage runs.
