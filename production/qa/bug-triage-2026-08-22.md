## 🔴 CRITICAL — BUG-063: a previously-fixed data-corruption bug was silently reintroduced 89 minutes before this review

The `/code-review` pass (see Systemic Issues + full findings below) caught a live regression:
`Assets/Script/StatSystem/Stat.cs:63-66` now reads

```csharp
#if UNITY_EDITOR
[SerializeField]
#endif
private List<StatModifier> modifiers = new List<StatModifier>();
```

introduced by commit `aa4e620` ("fix conflict DI", a merge-conflict resolution) — this directly undoes
`f5de65a` ("fix(stats): stop serializing Stat.modifiers so runtime buffs cannot leak"), the fix for the
exact incident CLAUDE.md's `NEW-4` entry documents (`STR +1 Flat` leaking into `PlayerStats.asset` /
`Test.asset`). `UNITY_EDITOR` is defined in every Editor session — precisely the condition under which
the original leak happened — so gating the attribute behind it does not avoid the bug, it reproduces it.
This is an **ADR-0001 architectural violation** (the ADR's Decision explicitly requires this field stay
unserialized), not a style nit. Filed as `production/qa/bugs/BUG-063.md`, S1, and placed at the top of the
P1 table below — it is a live, cheap-to-fix regression that should not wait behind the sprint's
longer-standing enemy-AI blocker.
