# BUG-099

**Title**: Doc sync `7d1b5c79` records BUG-096 as fixed — CLAUDE.md and `map-system.md` say marker-less rooms open their doors, but the fix was reverted
**Severity**: S3 (documentation drift that hides an open S1; no runtime effect of its own)
**Priority**: 2 (correct together with the BUG-096 owner decision)
**System**: Map / Room progression (`design/gdd/map-system.md`, Status: In Progress) + `CLAUDE.md`
**Found by**: Monthly module quality audit, delta run 2026-10-06 (branch `sprint-17`, HEAD `8da09b1a`)
**Status**: Open — static analysis

## Description

`7d1b5c79` ("docs: sync docs with code at 93ba6d8e", 2026-10-05) wrote that rooms with no
`Tile_Spawn_Enemy` marker open their doors on load, citing `40d2c793`:

- `CLAUDE.md:52` — "Rooms with no spawn marker open their doors immediately."
- `CLAUDE.md:612` — "Start/Rest/Shop/Buff carry NO spawn marker, so `LoadRoom()` opens their doors immediately (`40d2c793`)"
- `design/gdd/map-system.md:22`, `:381` (Edge-case table: "✅ Doors open on load"), `:443` (acceptance
  criterion ticked `[x]`)

The code at HEAD does not do this. `40d2c793` added the `spawnPositions.Count == 0` branch, and
`ac13ee4` removed it again (both are ancestors of HEAD). Today:

- `RoomGeneraterController.LoadRoom()` (`:134-144`) has only `!IsCleared` → swap doors to walls + emit
  `ON_GET_SPAWN_POSITIONS`, else → `OpenDoors()`. No empty-list branch.
- `EnemySpawner.OnGetSpawnPositions()` (`:41-45`) returns early with a `LogWarning` on an empty list, so
  `ON_DONE_SPAWN_ENEMY` / `ON_CLEAR_ENEMY` never fire.

That is exactly the open S1 **BUG-096**. The docs now state the opposite of the code, and they mark the
map acceptance criterion as met.

## Consequence

Anyone reading CLAUDE.md or the map GDD will believe the dungeon loop is unblocked and skip BUG-096.
The 2026-10-05 module audit scored `map-system.md` CRITICAL on BUG-096; the docs written later the same
day contradict that verdict.

## Fix

1. Owner decides BUG-096 (restore the `40d2c793` branch, or a different rule for non-combat rooms).
2. If the fix is restored: no doc change needed. If not: revert the four doc claims above to
   "⚠️ OPEN — BUG-096" and untick `map-system.md:443`.
3. `/doc-sync` should check that a cited fix commit is not followed by a revert before recording it as fixed.
