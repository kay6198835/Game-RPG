## Description

`Assets/Script/Character/Base/CharacterData.cs:2` has `using UnityEditor.Animations;` and `:20`
declares `[SerializeField] public AnimatorController animationController;`. The file is in the
runtime assembly with no `#if UNITY_EDITOR` guard. `UnityEditor` is not available to a Player build,
so `Assembly-CSharp` fails to compile there (historical Bug #10 pattern). Introduced by `041292ce`
"done flow pick champion" (2026-10-25); the field was `AnimatorOverrideController` before.

Second effect: `Assets/SO/Player/BaseData.asset:17` references an `AnimatorOverrideController`
(`fileID: 22100000`), which no longer matches the field type and loads as null. Paladin / Mage /
Archer reference `.controller` assets and are unaffected.

## Expected fix (owner)

Field type `RuntimeAnimatorController` (accepts both a controller and an override controller), drop
the `using UnityEditor.Animations;` line. Re-check `BaseData.asset` afterwards.

## How to verify

File → Build Settings → Build (any desktop target): the build compiles. In Play Mode, picking each
Champion still swaps the animator.
