**Priority**: 2 (one-line ordering fix; affects every pooled enemy from the second spawn on)

## Description

`d2d45973` (2026-11-07, auto-committed by the QA automation run `20261107-1437` from the owner's
working tree) added:

- `Entity.OnEnable()` → `core.ReloadCore()` (`Assets/Script/Character/Entity/Entity.cs:40`);
- `EntityInput.ReloadComponent()` → `spawnPoint = this.transform.position;`
  (`Assets/Script/Character/Entity/CoreComponent/EntityInput.cs:70-75`);
- and removed the commented `entityInput.SetSpawnPoint(positionRandom)` hint from `EnemySpawner`.

`Assets/Script/System/PoolableService/Pool.cs:51-52` re-uses a pooled object as:

```
reload.gameObject.SetActive(true);                              // OnEnable runs here
reload.gameObject.transform.SetPositionAndRotation(position, rotation);
```

So on every pooled re-spawn `OnEnable()` → `ReloadCore()` → `EntityInput.ReloadComponent()` reads
`transform.position` **before** the pool moves the enemy, and `spawnPoint` becomes the position where
the enemy was released (its last death). `EntityMovement.cs:150-152` uses `entityInput.SpawnPoint` as
the centre of the random wander node, so the enemy walks back toward that old spot. The first spawn
(`Instantiate` with a position) is correct; `EntityInput.Start()` (`:66`) also sets it.

Secondary: on the first `Instantiate`, `Entity.OnEnable()` runs right after `Entity.Awake()`, possibly
before `EntityCore.Awake()` has run `Setup()`, so `ReloadCore()` iterates an empty list — harmless
today, but the reload does not happen on first spawn.

## Expected fix (owner)

Set the anchor after the position is final: e.g. have `EnemySpawner` set it explicitly after
`Spawn()` (the removed `SetSpawnPoint` hint), or swap the two lines in `Pool.Reload()` so the object
is positioned before it is activated (check other pooled users first).

## How to verify

In `LoadRandomMap`, clear a room, move to another combat room; enemies re-used from the pool wander
around their new spawn markers, not toward the previous room. Inspect `EntityInput.spawnPoint` after
a re-spawn: it equals the new spawn position.
