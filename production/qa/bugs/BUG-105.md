## Description

`ddcc0a5c` (2026-09-01, "coding") renamed the serialized field in
`Assets/Script/Weapons/MeleeWeapon/AttackSO.cs:10` from `attackDamege` to `attackDamage` with no
`[FormerlySerializedAs("attackDamege")]`.

Assets written before the rename were never re-saved:

| Asset | Serialized key | Value Unity now loads |
|---|---|---|
| `Assets/SO/Weapons/MeleeWeapons/SnS_State1.asset:17` | `attackDamege: 55` | `attackDamage = 0` |
| `SnS_State2.asset` | `attackDamege` | `0` |
| `SnS_State3.asset` | `attackDamege` | `0` |

Assets authored after the rename carry the new key and are fine (`Knight_Attack1.asset`,
`Range Attack SO State 1-3.asset`).

Consumer: `WeaponHolderBase.CalculateCurrentDamage()` (`Assets/Script/Character/Base/WeaponHolderBase.cs:92-98`)
= `PhysicalDamage` + `CurrentStage.attackDamage` (+ crit). With `attackDamage = 0` every sword stage
deals the stat-only amount, and the three combo stages hit identically.

This is also a breach of the "Preserve intentional typos" convention in `CLAUDE.md`, which still lists
`attackDamege` as a serialized contract.

## Expected fix (owner)

Add `[FormerlySerializedAs("attackDamege")]` (namespace `UnityEngine.Serialization`) to the field, open
the three assets once and save so they migrate. Do not hand-edit the YAML.

## How to verify

Play Mode: hit an enemy with each sword stage and read the HP drop. Expected ≈ `PhysicalDamage + 55`
on stage 1 (minus target Defense); today it is `PhysicalDamage` only.
