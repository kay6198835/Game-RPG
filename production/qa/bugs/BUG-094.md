# BUG-094

**Title**: `RangeWeapon` rotates the character root on every attack — `firePoint` is overwritten with the owner transform
**Severity**: S2 (visible, gameplay-breaking; no error, no log)
**Priority**: 1 (blocks S16-05 / S16-07 ranged-weapon verification)
**System**: Weapons / RangeWeapon
**Found by**: Weekly wrap-up code review, 2026-09-28 (branch `sprint-16`, HEAD `5b035b7` "range weapon")
**Status**: ✅ Fixed in code (`b7a0af5`, 2026-09-28) — confirm in Play Mode

## Description

`5b035b7` added an override at `RangeWeapon.cs:28-32`:

```csharp
public override void Equid(IWeaponHolder weaponHolder)
{
    base.Equid(weaponHolder);
    firePoint = weaponHolder.OwnerTransform;   // character root (ICharacter.Transform)
}
```

`OnAttackEnter()` (`:34-38`) then does:

```csharp
firePoint.right = aim.AimDirection.normalized;
```

Assigning `Transform.right` rotates that transform. After equip, `firePoint` **is the character root**
(`WeaponHolderBase.OwnerTransform` → `ICharacter.Transform`), so every ranged attack rotates the whole
player (or enemy) GameObject around Z toward the aim.

The serialized `firePoint` authored on the weapon prefab is discarded on every equip.

## Consequence

- The player sprite, colliders and every child rotate with the aim on each shot. Nothing rotates it back.
- `PlayerManager.SpawnPlayer()` parents `Camera.main` to the player root (`PlayerManager.cs:35`), so the
  **camera rotates too**.
- Projectiles spawn at the character pivot, not a muzzle.

## Fix

Keep a dedicated fire-point child (the serialized field, or a child of the weapon/holder) and never
rotate the character root. Either:

- drop the `firePoint = weaponHolder.OwnerTransform` line and keep the authored fire point, or
- compute the angle from `aim.AimDirection` directly in `OnActivate()` and spawn at the holder position
  without writing to any transform's `right`.

## Verify

Play Mode: equip the ranged weapon, fire in four directions. The player sprite and the camera must not
rotate; projectiles must leave along the aim.

## Re-verification — 2026-09-29 (HEAD `7c637c0`)

`firePoint` is now a `Vector2` (`RangeWeapon.cs:7`) computed in `OnAttackEnter()` as owner position +
`aim.AimDirection * spawnOffset`; `Equid()` no longer assigns the owner transform and nothing writes
`.right` on any transform. The root can no longer be rotated.
Residual (tidy-up): `OnDrawGizmosSelected()` tests `firePoint != null` on a struct (always true) and
draws to `firePoint + firePoint * attackRange`, which is not the aim direction.
