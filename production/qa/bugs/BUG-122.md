# BUG-122

**Title**: `PlayerDeathState` emits `ON_PLAYER_DEATH` only on `StatusAnimation.EndRangeTrigger`, but every Paladin Die clip carries only `AnimationOnAction` — the player dies, the event never fires, no Game Over
**Severity**: S1 (death is a dead end: no Game Over panel, no respawn path; the run cannot continue)
**Priority**: 1 (blocks the death half of the demo loop; prerequisite of BUG-086 / BUG-087)
**System**: Player state machine, Animation (death clips), Life cycle
**Found by**: Friday automated QA (`qa-auto`, case QA-VIT-07), inbox note NOTE-20261101-1; confirmed by the 2026-11-07 wrap-up triage
**Status**: Open — confirmed at runtime (automated Play Mode, 10 of 10 runs since 2026-11-01) and by reading code
**Fixed in**: —

## Description

`Assets/Script/Character/Player/States/PlayerDeathState.cs:14-20` (at `sprint-21` `acacdf6c`):

```
public override void LogicUpdate()
{
    if (Status == StatusAnimation.EndRangeTrigger)
    {
        EventManager.Emit(EventID.ON_PLAYER_DEATH);
    }
}
```

`Status` reaches `EndRangeTrigger` only through the `AnimationFinishTrigger` Animation Event. All
eight Paladin death clips (`Assets/Animation/Player/Paladin/Basic/Die/Knight_Die_dir 0-7.anim`)
carry exactly one event, `AnimationOnAction` (→ `StatusAnimation.OnActivate`). So after lethal
damage the player enters `PlayerDeathState` with HP 0 and stays there; `ON_PLAYER_DEATH` is never
emitted and `RealPlayerDataProvider` (the only subscriber) never raises Game Over.

`4097be4c` / `1c3a34fc` (2026-11-05, death read from `ICharacterInput.IsDeath`) changed how the
player enters the death state, not how the state emits; QA run `20261105-1417` (`8140a56d`) and
`20261107-1437` (`5a3256e7`) still FAIL QA-VIT-07.

## Evidence

- QA-VIT-07 FAIL in every automated run since 2026-11-01 (runs `20261101-0150`, `-0221`,
  `20261105-1002`, `-1053`, `-1102`, `-1417`, `20261107-1437`, …): "ON_PLAYER_DEATH not emitted
  within 4s of death — death clip Knight_Die_dir 5, events: AnimationOnAction".
  Reports under `qa/weekly-automation:qa-automation/reports/`.
- QA-VIT-08 (event emitted once, not every frame) is SKIP because of this bug.

## Expected fix (owner — pick one)

1. Add an `AnimationFinishTrigger` event at the end of each Paladin Die clip (and the Archer / Mage
   death clips when they exist), or
2. make `PlayerDeathState` emit on the event the clips do carry (`OnActivate`), **once** (consume
   `Status` after emitting — that also closes BUG-086).

Mind the enemy side: `EntityDeathState` emits on `OnActivate`, and the shared clip shape matters
for NOTE-20261105-3 (closed by design — the spawner releases on the first emit).
