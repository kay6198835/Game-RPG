# BUG-114

**Title**: `VitalStatsBase` snapshots all 17 stats once in `Reborn()` — stat buffs / debuffs never reach weapon damage, crit or move speed until the next `Reborn()`
**Severity**: S2 (Paladin Blessing and stat items have no combat effect)
**Priority**: 2 (stat-reduction epic, story-003; after BUG-113)
**System**: Stats / Vitals
**Found by**: session stat-system review 2026-10-21 (NOTE-20261021-2); confirmed by weekly wrap-up triage 2026-10-25 at `sprint-19` `05dcf630`
**Status**: Open — confirmed by reading code; not yet observed in Play Mode
**Fixed in**: —

## Description

`Assets/Script/Character/Base/VitalStatsBase.cs:26` — `Reborn()` copies the full stat set into
`currentStats` once. `ApplyBuffDebuff()` / `BuffDebuffForDuration()` add modifiers to the stat SO only
and never refresh that snapshot. Readers of the snapshot via `GetCurrentStatValue()`:

- `WeaponHolderBase.cs:83-86` — PhysicalDamage, CritChance, CritDamage
- `PlayerMoveState.cs:19` — MoveSpeed

So a buff changes nothing in combat; and a `Reborn()` that runs while a timed buff is active keeps the
buffed value after the buff expires. Relates to BUG-100 (modifier source) and BUG-113 (max definition).

Planned fix: `production/epics/stat-reduction/story-003-vitals-resources-only.md`.

## Expected fix (owner)

`currentStats` holds resource stats only (HP, Mana); every other stat is read live from `IStatService`;
clamp current HP / Mana when their max changes.

## How to verify

Cast Blessing (or pick up a STR item), hit an enemy — damage must rise while the buff is active and
return to normal when it expires.
