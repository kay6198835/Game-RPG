# BUG-090

**Title**: `Has Enough Mana Condition.asset` is orphaned — its script was deleted in `2a83469` but the asset and two references to it remain
**Severity**: S3 (asset hygiene; the two referencing assets are the already-broken ShootSpirit pair)
**Priority**: 3
**System**: Abilities v2 / Conditions — SO assets
**Found by**: Post-fetch source re-verification, 2026-09-22 (branch `origin/feature/fix-player-control`, HEAD `2a83469`)
**Status**: Open — CONFIRMED by GUID resolution

## Description

Commit `2a83469` deleted `Assets/Script/System/Abilities/Conditions/HasEnoughManaCondition.cs` and
its `.meta` — the correct fix for **BUG-077**, and it also cleared the condition out of all four
Paladin ability assets (each now reads `Conditions: []`). That part is clean.

What it did not remove is the condition **asset** itself:

```
Assets/SO/Skill/Conditions/Has Enough Mana Condition.asset        (428 B, still present)
Assets/SO/Skill/Conditions/Has Enough Mana Condition.asset.meta   (guid 02cbacd1d0342774abb852a2ed63f9b4)
```

Its `m_Script` points at the deleted class:

```yaml
m_Script: {fileID: 11500000, guid: 6f896bb258601fc4cb5fc183399618ea, type: 3}
m_Name: Has Enough Mana Condition
```

`6f896bb258601fc4cb5fc183399618ea` is the guid from the deleted
`HasEnoughManaCondition.cs.meta` (read out of `git show d17fcc5:…`). Resolving it against every
`.meta` under `Assets/` at HEAD returns **0 files**. Unity will show this asset as
*"The associated script can not be loaded"* and serialise it as a null `MonoBehaviour`.

Two assets still reference it by its own guid `02cbacd1d0342774abb852a2ed63f9b4`:

```
Assets/SO/Skill/ShootSpirit/MainEffect/ShootSpirit.asset
Assets/SO/Skill/ShootSpirit/SpiritBomd.asset
```

Both are already flagged under **BUG-073** for referencing a *different* missing script
(`ac9ac7c011812d042ac992007bc0cf48`, also 0 files). This is a second missing-script reference in the
same pair, from a different cause. `PlayerTest.prefab` still reaches `SpiritBomd.asset`, so the
broken references are reachable from a live prefab, not only from orphaned files.

## Why it matters, given it is S3

On its own, a null condition entry is harmless at runtime: `AbilityInstance.CanStart()` →
`AbilityDefinition.TryStart()` walks `Conditions`, and a missing-script entry deserialises to a
Unity-null element.

⚠️ But `TryStart()` (`AbilityDefinition.cs:50-64`) **lost the null-element guard** that the deleted
`ValidateConditions()` had (`if (condition == null) continue;`). It calls `condition.IsMet(…)`
directly. So if either ShootSpirit asset is ever bound to a slot, the first activation throws a
`NullReferenceException` inside `TryStart()`. That regression is filed separately as **BUG-091**;
this bug is what would trigger it.

## Reproduction

```bash
grep -rl "02cbacd1d0342774abb852a2ed63f9b4" Assets/          # 3 hits: the .meta + the two ShootSpirit assets
grep -rl "6f896bb258601fc4cb5fc183399618ea" Assets/ --include=*.meta   # 0 hits — the script is gone
```

In the Editor: select `Assets/SO/Skill/Conditions/Has Enough Mana Condition.asset` — the Inspector
shows a missing-script warning.

## Expected

Deleting a `ScriptableObject` class removes its assets and every reference to them in the same
commit, so the project has no dangling guids.

## Fix sketch

Editor-side, no code:

1. Delete `Assets/SO/Skill/Conditions/Has Enough Mana Condition.asset` **and** its `.meta`.
2. Clear the two `Conditions` references in `ShootSpirit.asset` and `SpiritBomd.asset`.
3. Bundle with **BUG-073** — same two assets, same class of problem, one Editor session. Decide there
   whether the ShootSpirit pair is being kept at all; if it is being deleted, this bug closes with it.

## Notes

- The Paladin ability assets were cleaned correctly in the same commit (`Conditions: []` × 4), which
  is why this only survives on the older ShootSpirit content.
- This is the third missing-script reference recorded in this project
  (BUG-073 `ac9ac7c0…`, BUG-073's prefab chain, and now `6f896bb2…`). All three came from deleting a
  `.cs` without sweeping `.asset` files. A pre-push guid-resolution check would catch the class.

Owner position: *"90 đã xóa script đó"* — that script was deleted.

Correct, and that is exactly what this bug depends on. Two different files are involved and only one
of them is gone:

| File | What it is | State at HEAD `2a83469` |
|---|---|---|
| `Assets/Script/System/Abilities/Conditions/HasEnoughManaCondition.cs` | the **C# class** | ✅ **deleted** in `2a83469` — this is BUG-077, correctly closed |

Deleting the class is what *creates* the problem: a `.asset` stores its type as a guid pointing at
the script file, so removing the script turns every instance of it into a missing-script object.

### Why it is worth the two minutes despite being S3

`ShootSpirit.asset` is the **one asset in the whole project** with a populated `SubConditions` list
(every Paladin effect has `SubConditions: []`). Its entry is this orphan. So it is the single asset
that can reach the missing null-element guard in `AbilityDefinition.TryStart()` — see **BUG-091**,
where the owner has since added `if (condition == null) continue`, which now absorbs it. With that
guard in place this drops to pure hygiene.
