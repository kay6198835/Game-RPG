# BUG-115

**Title**: The player mutates the shared, committed `BaseStatsSO` asset — weapon modifiers leaked into all four player stat assets, and stats / spent points accumulate across death and New Game
**Severity**: S2 (data corruption in git + wrong stats on every later run; play continues). Inbox guess was S1 — lowered because nothing blocks a run.
**Priority**: 1 (stat-reduction epic, story-009; clean the four assets in the same change)
**System**: Stats
**Found by**: session stat-system review 2026-10-21 (NOTE-20261021-3); confirmed by weekly wrap-up triage 2026-10-25 at `sprint-19` `05dcf630`
**Status**: Open — confirmed by reading code and asset YAML; cross-run growth not yet observed in Play Mode
**Fixed in**: —

## Description

`Assets/Script/Character/Player/CoreComponent/StatHandler.cs:21` — `ResolveProfile()` returns the
Inspector `statsSO` or the `PlayerData` profile itself, never a runtime clone (`EntityStatsHandler`
already uses `Instantiate()`).

**Evidence in git:** `Assets/SO/Stat/Player/PaladinStats.asset` carries runtime modifiers on
`targetStat: 0` (STR, `:26`) and `targetStat: 102` (PhysicalDamage, `:85`) — the `authoredModifiers`
of `Assets/SO/Weapons/PaladinWeapon/SnS_Stat.asset`, saved through the Editor-only `[SerializeField]`
of BUG-063 (accepted, deferred). The 2026-10-21 review found the same in `ArcherStats`, `MageStats` and
`BaseStats` (Archer / Mage inherited it when duplicated in `ada2c1a`). Second occurrence (first:
sprint-10).

Build-time risk (static): the SO stays loaded across `LoadSceneMode.Single`; `Weapon` removes its
modifiers only in `UnEquid()` (`Weapon.cs:111`, no `OnDestroy`), so each death →
`RealPlayerDataProvider.Respawn()` or New Game re-adds +2 STR / +10 PhysicalDamage, and spent stat
points (`levelUpValue`) carry across runs.

Relates to BUG-063, BUG-111 (`statsSO` raw-field NRE in the subscribe helpers).
Planned fix: `production/epics/stat-reduction/story-009-player-runtime-stat-clone.md`.

## Expected fix (owner)

Runtime clone in `StatHandler.ResolveProfile()` assigned to `statsSO` (inspectable as "… (Runtime)"),
rebuilt on `SetCharacterData()`; use `StatsSO` in the subscribe helpers; remove the leaked modifiers
from the four assets.

## How to verify

Play, die, respawn, open the stats panel (C): STR / PhysicalDamage identical to the first run. Exit Play
Mode: `git status` shows no dirty `Assets/SO/Stat/Player/*.asset`.
