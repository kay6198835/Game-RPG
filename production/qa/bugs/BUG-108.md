# BUG-108

**Title**: `CharacterData` dropped its `[FormerlySerializedAs]` attributes — the five `Enemy - Knight*` `EntityData` assets still store `statsSO` / `weaponSO`, so enemies load `Stats = null` and `EntityStatsHandler` calls `Instantiate(null)`
**Severity**: S1 (every Knight enemy throws on its first stat read; combat rooms cannot be cleared)
**Priority**: 1 (restore the attributes, or re-save the assets with them in place)
**System**: Character data / Stats (serialization)
**Found by**: weekly wrap-up 2026-10-19 code review (NOTE-20261019-3, review-flow R3.5 — renamed serialized field still named elsewhere); confirmed in the same triage at `sprint-18` `0def62ab`
**Status**: Open — confirmed by reading code and asset YAML; not yet observed in Play Mode
**Fixed in**: —

## Description

`cae75317` "add asset" (2026-10-19, merged to `sprint-18` by `0def62ab`) changed
`Assets/Script/Character/Base/CharacterData.cs:15-16`:

| Before | After |
|---|---|
| `[SerializeField, FormerlySerializedAs("statsSO")] private BaseStatsSO stats;` | `[SerializeField] private BaseStatsSO stats;` |
| `[SerializeField, FormerlySerializedAs("<AbilityBindings>k__BackingField")] private List<AbilityBinding> abilityBindings` | `[SerializeField] private List<AbilityBinding> abilityBindings` |
| `[SerializeField, FormerlySerializedAs("weaponSO")] private WeaponSO defaultWeapon;` | removed (replaced by `Weapon` property) |

The player assets were re-saved (`Paladin.asset`, `Archer.asset`, `Mage.asset`, `BaseData.asset` store
`stats:` / `abilityBindings:`). The enemy assets were not:

| Asset (`m_Script` = `EntityData`, guid `a2c1885a…`) | Key on disk |
|---|---|
| `Assets/SO/Enemy/Enemy - Knight.asset:15,25` | `statsSO:`, `weaponSO:` |
| `Enemy - Knight 1.asset` … `Enemy - Knight 4.asset` (`:15,26`) | `statsSO:`, `weaponSO:` |

Unity therefore loads `EntityData.Stats = null` (and no weapon) for every Knight. Consumer:
`EntityStatsHandler.ResolveProfile()` (`EntityStatsHandler.cs:10-17`) → `Instantiate(source)` with
`source == null` → `ArgumentException`, then `source.name` → NRE. `EntityEffectStats.cs:20` also passes
`Data.Stats` on.

Same class of defect as BUG-105 (`attackDamege`). Data is not yet lost on disk — the old keys are still
in the files, so restoring the attributes recovers it, until someone re-saves an asset without them.

## Expected fix (owner)

Restore `[FormerlySerializedAs("statsSO")]` on `stats`. Decide whether `weaponSO` (a `WeaponSO`
reference) should migrate to the new `Weapon` (a `Weapon` component reference) — the types differ, so
the enemy weapons must be re-authored on each asset. Then open and save the five assets.

## How to verify

Play Mode: enter a combat room; Knights spawn with an HP bar, take damage and die; no
`ArgumentException` from `EntityStatsHandler`. Asset YAML after save shows `stats:`.
