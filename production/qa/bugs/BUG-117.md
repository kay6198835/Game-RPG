# BUG-117

**Title**: Vital (current HP / Mana) modifiers cannot be authored and invert when they could — `VitalModifier` is not serializable, a negative value heals, and a reduction is applied twice
**Severity**: S2 (every instant recovery / reduction stat effect is a silent no-op today; wrong sign once fixed)
**Priority**: 2 (fix before authoring any heal / damage-over-stat effect asset)
**System**: Stats / Abilities v2 (`StatModifierGroup`, `EffectReceiverBase`)
**Found by**: weekly wrap-up code review 2026-10-31 (NOTE-20261031-1) at `sprint-20` `2276049e`
**Status**: Open — confirmed by reading code and asset YAML; not yet observed in Play Mode
**Fixed in**: —

## Description

Three defects in the effect-component path landed this week (`786c031b`, `6e484f0c`):

1. `Assets/Script/System/StatSystem/VitalModifier.cs:4` — `public class VitalModifier` has no
   `[System.Serializable]`. Unity therefore never serializes
   `StatModifierGroup.vitalModifiers` (`StatModifierGroup.cs:27-28`): the list is not shown in the
   Inspector and cannot be authored. `git grep vitalModifiers -- Assets/SO` returns 0 hits, so every
   `RecoveryReductionStatsEffect` asset iterates an empty list in
   `EffectReceiverBase.AdjustCurrentStats()` and does nothing.
2. `VitalModifier.ImpactType` (`:15`) is derived from the sign of `value` (negative = Reduction), but
   `EffectReceiverBase.AdjustCurrentStats()` passes `modifier.Value` unchanged to
   `vital.Reduction()` (`EffectReceiverBase.cs:49,51`). `VitalStatsBase.Reduction()` does
   `current - amount` (`VitalStatsBase.cs:77-83`), so a negative amount **raises** the stat.
3. The Reduction branch calls `vital.Reduction(...)` twice — once inside the `Enum.IsDefined` check
   (`:49`) and once unconditionally (`:51`).

Net effect once (1) is fixed: a "deal 10 HP" modifier heals 20.

⚠️ The owner's working tree had uncommitted edits to `EffectReceiverBase.cs` and related files at
triage time; re-read after the next push.

## Expected fix (owner)

`[System.Serializable]` on `VitalModifier`; pass `Mathf.Abs(modifier.Value)` (or `-value`) to
`Reduction()`; delete the duplicate call at `:51` (keep the guarded one).

## How to verify

Author a `RecoveryReductionStatsEffect` with HP −10 on a test ability, cast it on a `TrainingDummy`
in the CombatTest scene: HP drops by exactly 10.
