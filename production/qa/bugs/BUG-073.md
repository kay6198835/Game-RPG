# BUG-073

**Title**: Deleted ability runtime scripts are still referenced by live assets — `ShootSpirit.asset` and `SpiritProjcetile.prefab` now have missing-script references
**Severity**: S2 (asset break — the original Abilities v2 proof-of-wiring ability no longer works)
**System**: Abilities v2 / Assets
**Found by**: `pm-weekly-wrapup` code-review pass, 2026-09-19 (autonomous); verified by GUID grep against pre-deletion `.meta` files
**Status**: Open

## Description

Commit `bbc2b8c` deleted `ShootObjectEffect.cs`, `SpiritOrbProjectile.cs`, `SpiritDoTBehaviour.cs`,
`DamageInFrontEffect.cs`, `LungeForwardEffect.cs`, `PlayDebugLogEffect.cs`, `AbilityRuntimeHelpers.cs`.
GUID search over `Assets/`:

- `ShootObjectEffect` (`ac9ac7c0...`) is still referenced by `Assets/SO/Skill/ShootSpirit/MainEffect/ShootSpirit.asset`
- `SpiritOrbProjectile` (`405e5c1b...`) is still referenced by `Assets/Prefab/Bullet/SpiritProjcetile.prefab`

Unity will show "Missing (Mono Script)" and the ability will do nothing. `CLAUDE.md` still cites these
assets as the live proof that v2 is wired.

## Suggested Fix

Either re-point the assets to `SpawnProjectileEffect` / `SpawnProjectileBase` equivalents, or delete the
orphaned assets deliberately. Update `CLAUDE.md` after the decision.

## Re-verification — 2026-09-22 (branch `main`, HEAD `d17fcc5`, merge of `e2cb75e`)

**Raised from "suspected missing-script reference" to CONFIRMED, by GUID resolution.**

### Evidence

`Assets/SO/Skill/ShootSpirit/MainEffect/ShootSpirit.asset:12`

```yaml
m_Script: {fileID: 11500000, guid: ac9ac7c011812d042ac992007bc0cf48, type: 3}
m_Name: ShootSpirit
```

Resolving that GUID against every `.meta` file under `Assets/`:

```
$ grep -rl "ac9ac7c011812d042ac992007bc0cf48" Assets --include=*.meta | wc -l
0
```

No file in the project claims that GUID. The asset is a `MonoBehaviour` with a missing script — it
will show as "The associated script can not be loaded" in the Inspector and its serialized payload
(`OrbPrefab`, `Speed`, `SpawnOffset`, `SubConditions`, …) is unreachable.

The referenced script was one of the four effect classes deleted in the sprint-13/14 rewrite
(`DamageInFrontEffect` / `LungeForwardEffect` / `ShootObjectEffect` / `PlayDebugLogEffect`); the
asset was not deleted with them.

### Reference chain is still live

`Assets/Prefab/Player/PlayerTest.prefab` still reaches this chain via
`Assets/SO/Skill/ShootSpirit/SpiritBomd.asset` (GUID `9de99cc2a34f9d345ac7cffecd4b1b27`), so the
broken asset is loaded, not orphaned. `ShootSpirit.asset` also still references the live
`Has Enough Mana Condition.asset` (GUID `02cbacd1d0342774abb852a2ed63f9b4`) in its `SubConditions`.

### Related dead name in live code

`SpawnEffectBase.cs:14` and `:30` still log with the prefix of a deleted class:

```csharp
Debug.LogWarning("[ShootSpiritOrbEffect] OrbPrefab chưa được assign.");
Debug.LogWarning("[ShootSpiritOrbEffect] OrbPrefab thiếu component SpiritOrbProjectile.");
```

`ShootSpiritOrbEffect` and `SpiritOrbProjectile` were both deleted in the same rewrite. These
strings will mislead whoever hits the warning — which, per **BUG-078** scenario 2, can be every
single cast. Fix them in the same pass.

### Fix scope

Editor-assisted: either repoint `ShootSpirit.asset` / `SpiritBomd.asset` at a surviving effect class
(`SpawnProjectileEffect` is the nearest equivalent), or delete both assets and remove the
`PlayerTest.prefab` reference. Then correct the two log prefixes in `SpawnEffectBase.cs`.
