# BUG-084

**Title**: No `.asmdef` exists anywhere under `Assets/`, and `tests/` sits outside `Assets/` — Unity Test Runner cannot compile or discover a test even if one is written
**Severity**: S2 (process blocker — makes TD-014 unfixable as currently scoped, not merely unfixed)
**Priority**: 2
**System**: Project configuration / Test infrastructure
**Found by**: Documentation/source re-verification pass, 2026-09-22 (branch `main`, HEAD `d17fcc5`, merge of `e2cb75e`)
**Status**: Open — CONFIRMED

## Description

Two independent facts make the project's test directories non-functional. Either one alone would
be enough.

### 1. Zero assembly definitions

```
$ find Assets -name "*.asmdef" | wc -l
0
```

`com.unity.test-framework@1.1.33` is present in `Packages/manifest.json`, but Unity Test Runner
discovers tests only from assemblies that reference `UnityEngine.TestRunner` /
`UnityEditor.TestRunner`. Those references can only be declared in an `.asmdef`. With no `.asmdef`
in the project, all gameplay code compiles into the default `Assembly-CSharp`, which cannot
reference the test framework. A `[Test]`-attributed class placed anywhere under `Assets/` today
would compile into `Assembly-CSharp` and never appear in the Test Runner window.

### 2. The test directories are outside the Unity asset tree

```
tests/EditMode/.gitkeep
tests/PlayMode/.gitkeep
tests/playtest/
```

`tests/` is a sibling of `Assets/`, not a child. Unity compiles **only** what is under `Assets/`
(and `Packages/`). Nothing in `tests/` is ever seen by the compiler, with or without an `.asmdef`.
Both directories still contain nothing but `.gitkeep`, as they have for the whole project history.

### Stale artifact — not evidence of a working setup

`GameRPG.Combat.EditModeTests.csproj` at the repo root declares
`<AssemblyName>GameRPG.Combat.EditModeTests</AssemblyName>` and two compile items:

```xml
43:  <Compile Include="Assets\Tests\EditMode\AttackTimelineTests.cs" />
44:  <Compile Include="Assets\Tests\EditMode\ComboResolverTests.cs" />
```

Neither file exists; `Assets/Tests/` does not exist. The file is **untracked** — `.gitignore:42`
ignores `*.csproj`, and `git ls-files` does not know it. It is a stale IDE artifact left on one
machine from an `.asmdef` that was deleted without regenerating project files. It is not a test
setup, and it will not be recreated for anyone else who clones the repo.

## Impact

TD-014 ("0 test files") has been carried as an *Ongoing* XL item since 2026-05-31, and sprint-14
S14-13 / sprint-15 S15-N-series repeatedly schedule "write the first EditMode test" as a 0.3d task
paired with BUG-066/BUG-070. That estimate is wrong: the task cannot start. Writing the first test
requires a prior infrastructure step that no sprint has ever scoped.

This is the *precondition* of TD-014, not a symptom of it, which is why it is filed separately.

## Suggested Fix

Ordered, and all of it is a prerequisite to any test story:

1. Decide where tests live. The Unity-native answer is `Assets/Tests/EditMode/` and
   `Assets/Tests/PlayMode/`; the `tests/` tree outside `Assets/` can stay for `tests/playtest/`
   (manual playtest evidence, which is not compiled) but must stop being advertised as the home of
   EditMode/PlayMode tests. `.claude/rules/test-standards.md` currently points at
   `tests/EditMode/` / `tests/PlayMode/` and needs updating with whatever is decided.
2. Add a runtime `.asmdef` for gameplay code (e.g. `Assets/Script/GameRPG.asmdef`) so test
   assemblies have something to reference. Note this is a breaking change in its own right: it
   splits `Assembly-CSharp` and will surface every implicit cross-directory dependency at once.
   Budget for it.
3. Add `Assets/Tests/EditMode/GameRPG.EditModeTests.asmdef` with
   `"references": ["GameRPG", "UnityEngine.TestRunner", "UnityEditor.TestRunner"]`,
   `"includePlatforms": ["Editor"]`, and the `nunit.framework.dll` precompiled reference.
4. Delete the stale root `GameRPG.Combat.EditModeTests.csproj` (untracked; local cleanup only).
5. Re-estimate TD-014 and any sprint story that depends on it.
