# BUG-080

**Title**: `ResourceReceiver.vitalStatsComponent` is only ever assigned inside `ReceverModifierGroup()` — every other public method dereferences a null field
**Severity**: S1 (NullReferenceException on the live item-pickup path)
**Priority**: 1
**System**: Player / Core components / Item system
**Found by**: Documentation/source re-verification pass, 2026-09-22 (branch `main`, HEAD `d17fcc5`, merge of `e2cb75e`)
**Status**: Open — CONFIRMED (static read; not run in Play Mode)

## Description

`Assets/Script/Character/Player/CoreComponent/ResourceReceiver.cs`:

```csharp
5:    VitalStatsComponent vitalStatsComponent;          // never initialised in Awake/Start
...
11:    public void ReceverModifierGroup(StatModifierGroup statModifierGroup)
13:        Core.GetCoreComponent<VitalStatsComponent>(out vitalStatsComponent);   // the ONLY writer
14:        vitalStatsComponent.ApplyBuffDebuff(statModifierGroup);
```

Line 13 is the only assignment to the field in the whole class. Three public methods read it
without ever resolving it:

| Line | Method | Reads |
|---|---|---|
| 19 | `Recovery(StatType, float)` | `vitalStatsComponent.Recovery(...)` |
| 23 | `Reduction(StatType, float)` | `vitalStatsComponent.Reduction(...)` |
| 27 | `BuffDebuffForDuration(...)` | `vitalStatsComponent.BuffDebuffForDuration(...)` |

`TakeDamage()` (`:29-35`) is unaffected: it resolves into a **local** variable that shadows the
field (`:31 Core.GetCoreComponent(out VitalStatsComponent vitalStatsComponent);`), so it never
touches the field at all. That shadowing is also why the bug has stayed invisible in damage
playtests.

This is reachable today. `RecoveryEffectDefinition.cs:13` calls
`IResourceReceiver.Recovery(StatType.HP, amount)` directly — picking up any recovery item before
any buff/debuff item has been picked up in the same session throws.

## Reproduction

1. Enter Play Mode in `LoadRandomMap.unity` with a fresh player.
2. Pick up an item whose `ItemSO.ItemEffects` contains a `RecoveryEffectDefinition`
   (do **not** pick up a `StatModifierEffectDefinition` item first).
3. Observe `NullReferenceException` from `ResourceReceiver.Recovery`.

## Suggested Fix

Resolve once in `Awake()`/`Start()` like every other core component does, and drop the per-call
resolution in `ReceverModifierGroup()` and the shadowing local in `TakeDamage()`:

```csharp
protected override void Start()
{
    base.Start();
    Core.GetCoreComponent(out vitalStatsComponent);
}
```
