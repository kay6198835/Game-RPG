# BUG-126

**Title**: `TMP_TextInfoDebugTool.cs` has `using UnityEditor;` outside `#if UNITY_EDITOR` — expected to break every Player build
**Severity**: S2 (blocks a Player build; invisible in the Editor)
**Priority**: 2 (one-line fix; must land before any demo build)
**System**: Build / third-party samples (`Assets/TextMesh Pro/Examples & Extras/`)
**Found by**: automated QA run `20261114-2329` / `20261114-2357`, case QA-STATIC-05 (inbox note NOTE-20261115-4), re-read at `sprint-22` `ff7f3ecb` by the 2026-11-15 wrap-up
**Status**: Open — confirmed by reading code; not checked with a Player build
**Fixed in**: —

## Description

`Assets/TextMesh Pro/Examples & Extras/Scripts/TMP_TextInfoDebugTool.cs:4` is `using UnityEditor;`
at file scope. The class body is guarded from `:14` (`#if UNITY_EDITOR`), but the `using` directive
is not. The file has no assembly definition of its own, so it compiles into `Assembly-CSharp`, which
ships in a Player build where the `UnityEditor` namespace does not exist.

The file has been unchanged since `07676e27` (2025-03-02). It surfaced only now because QA-STATIC-05
mapped every `UnityEditor` finding to BUG-116 until BUG-116 was set Fixed on 2026-11-07.

## Expected fix (owner)

Move the `using UnityEditor;` inside the `#if UNITY_EDITOR` block, or delete
`Assets/TextMesh Pro/Examples & Extras/` (sample content, not used by the game).

## How to verify

QA-STATIC-05 passes; a Player build (File › Build Settings › Build) compiles.
