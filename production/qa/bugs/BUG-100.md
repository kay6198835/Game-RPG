# BUG-100

**Title**: Timed buff expiry strips every stat modifier on the character — permanent item buffs and overlapping timed buffs share one modifier source
**Severity**: S2 (gameplay value silently lost; no error, no log)
**Priority**: 2
**System**: Character / Stats (`VitalStatsBase`), Items, Abilities v2
**Found by**: Project review, 2026-10-08 (branch `sprint-17`, HEAD `1b24ef7b`) — static analysis
**Status**: Open — static analysis; confirm in Play Mode

## Description

`VitalStatsBase` uses `this` (the vitals component) as the modifier **source** for both kinds of buff:

- `ApplyBuffDebuff()` (`Assets/Script/Character/Base/VitalStatsBase.cs:41-45`) — permanent; called by
  item pickups through `StatModifierEffectDefinition.cs:12`.
- `ApplyDebuffForDuration()` (`:116-121`) — timed; called by `BuffDebuffStatsForDuration.cs:12`, which
  the Paladin **Blessing** ability uses (`Assets/SO/Skill/Paladin/Ability/Blessing/Effect/Paladin Buff - Debuff Stat Effect.asset`).

When the timed coroutine ends it calls `statHandler.RemoveModifiersFromSource(this)` (`:120`).
`BaseStatsSO` removes modifiers by source reference, so this removes **every** modifier added by
either method, not only the one that expired.

The behaviour predates `7f632021` (2026-10-07); that commit rewrote lines 43, 118 and 120 to the new
`StatModifierGroup.Modifiers` API without changing the source argument.

## Reproduction (expected, not yet run)

1. Start a run, pick up an item with a `StatModifierEffectDefinition` (e.g. +STR).
2. Cast Blessing; wait for its duration to end.
3. Open the stats panel.

**Expected**: item bonus remains; only Blessing's modifiers are removed.
**Actual (by reading)**: item bonus is gone as well. Casting Blessing twice with overlapping durations
ends both buffs at the first expiry.

## Suggested direction (not applied)

Give each application its own stable source token (e.g. a new `object` per timed application, kept
by the coroutine; the item instance or effect asset + owner for permanent ones), consistent with the
`StatModifierGroup` doc comment: "source must be a stable reference of the thing that owns the buff".
