# BUG-098

**Title**: Enemy-spawn GDD and ADR-0003 name a `RarityTier` enum that no longer exists — code renamed it `RarityTierEnemy`
**Severity**: S4 (documentation drift on an Approved module; no runtime effect)
**Priority**: 3 (fix with the next `/consistency-check` on `enemy-spawn-system.md`)
**System**: Enemy Spawn & Per-Room Management (`design/gdd/enemy-spawn-system.md`, Status: Approved)
**Found by**: Monthly module quality audit, 2026-10-05 (branch `sprint-17`, HEAD `d3a57f0`)
**Status**: Open — static analysis

## Description

`853fe39` ("coding", 2026-09-06 — Item system work, not an enemy-spawn story) renamed the enemy rarity
enum in `Assets/Script/Database-SO/Modal/RoomModel.cs`:

- `public enum RarityTier` → `public enum RarityTierEnemy` (`RoomModel.cs:110`)
- `EnemyModal.rarityTier` is now typed `RarityTierEnemy` (`RoomModel.cs:107`)

The rename made room for a second, unrelated enum `RarityTierItem` in `System/Item/DepotItem.cs:201`.

No document followed:

- `design/gdd/enemy-spawn-system.md` names `RarityTier` throughout, and its 2026-09-11 re-verification
  banner (`:34`) states that the `RarityTier` rules "still match" — that pass ran five days after the
  rename and did not notice it.
- `docs/architecture/adr-0003-enemy-spawn-selection-candidate-pool.md` (Accepted) shows
  `public enum RarityTier` (`:70`) and `public RarityTier rarityTier;` (`:84`) as the decided shape.
- `CLAUDE.md` Repository Layout says `RoomModel.cs` "also declares … the RarityTier enum".

`grep "enum RarityTier\b"` over `Assets/Script` returns 0 hits.

Serialized assets are unaffected: the enum is stored as an integer and the member values
(`Common = 50`, `Rare = 30`, …) did not change.

## Why it matters

This is the only `Approved` module in the project. Code written from the GDD or ADR will not compile,
and the GDD's own "did not drift" claim is now false. It is also a cross-module impact case: the
change came from Item-system work, with no enemy-spawn story attached.

## Fix

Docs only. Replace `RarityTier` with `RarityTierEnemy` in the GDD, ADR-0003 (as an amendment note, not
a rewrite of the decision) and CLAUDE.md, and add a line explaining why it was renamed
(`RarityTierItem` exists beside it).

## Verify

`grep -rn "RarityTier\b" design docs CLAUDE.md` returns only historical/explanatory mentions.
