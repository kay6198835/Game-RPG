## Description

`Assets/Script/System/Abilities/Runtime/SpawnMono/DamagesInManyPos.cs` (added `5c8245c9`, extended
`cae75317`):

1. `OnEnable()` calls `SetDir(_context.DirectionIndex)`. `_context` is assigned only in
   `SpawnMono.Launch()` (`SpawnMono.cs:13`), which `SpawnEffectBase` calls **after**
   `Pool.Spawn()` has activated the object. On the first spawn `_context` is null →
   `NullReferenceException`; on every pooled re-use it holds the **previous** cast's context, so the
   impact pattern follows the old aim direction.
2. `OnSkillEnd() => Destroy(gameObject)` destroys a pooled instance instead of
   `DespawnOneSelf()` / `Pool.Release()`; the pool keeps a dead reference.
3. `damagePerArrow` is a fixed serialized `int` and ignores the caster's stats, unlike
   `SpawnSummonEffect` (`baseDamage + PhysicalDamage`). Design question, noted only.
4. Unused `using Unity.VisualScripting`.

## Expected fix (owner)

Override `Launch()` and call `SetDir(context.DirectionIndex)` there (after `base.Launch`); end with
`DespawnOneSelf()`.

## How to verify

Play Mode as Archer: cast Rain Arrows twice, aiming in two different directions — no exception, the
second impact pattern follows the second aim, and the pool count stays stable.
