# BUG-093

**Title**: `SpawnEffectBase` no longer reads `context.Forward` — projectile abilities always fire to the right
**Severity**: S2 (feature broken silently — no error, no log)
**Priority**: 2
**System**: Abilities v2 / Effects
**Found by**: Daily standup source read, 2026-09-28 (branch `sprint-15`, HEAD `5b035b7` "range weapon")
**Status**: ⚠️ Open — static analysis; confirm in Play Mode

## Description

`5b035b7` commented out the four lines in `SpawnEffectBase.Apply()` (`SpawnEffectBase.cs:19-22`)
that computed `dir` from `_context.Forward`. Nothing else writes `dir`.

`SpawnProjectileEffect.Angle()` (`:13-19`) and `SpawnPos()` (`:31-34`) still read `dir`:

```csharp
if (dir.sqrMagnitude < 0.01f)
    dir = Vector2.right;       // first cast: dir is (0,0) -> forced to right
dir.Normalize();
return Mathf.Atan2(dir.y, dir.x) * Mathf.Rad2Deg;
```

So the first cast sets `dir = Vector2.right`, and because effect assets are shared single-instance
`ScriptableObject`s, that value is kept for every later cast by every owner until domain reload.

## Consequence

Every `SpawnProjectileEffect` ability (Paladin Blessed Slash) spawns at `Origin + right * SpawnOffset`
and flies at 0°, regardless of aim. `SpawnSummonEffect` overrides `Angle()` and is not affected by
the angle, but check its `SpawnPos()` if it reads `dir`.

## Fix

Either restore the four lines, or move the `Forward → dir` computation into
`SpawnProjectileEffect.Angle()`. Do not leave the value to persist on the asset — compute it per cast
from `_context.Forward` (see the per-cast-state rule in `.claude/rules/weapon-skill-code.md`).

## Verify

Play Mode: aim left/up/down and cast Blessed Slash — the projectile must follow the aim.
