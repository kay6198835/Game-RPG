# BUG-082

**Title**: Null check placed *after* the dereference — `if (Costs.Count == 0 || Costs == null)` can never reach its null test
**Severity**: S3 (latent — Unity's serializer hides it on asset-loaded instances; live on any code-constructed instance)
**Priority**: 3
**System**: Abilities v2 / Core
**Found by**: Documentation/source re-verification pass, 2026-09-22 (branch `main`, HEAD `d17fcc5`, merge of `e2cb75e`)
**Status**: ✅ FIXED — committed 2026-09-25 (was: working tree, uncommitted). The last residual named in the 2026-09-22 entry closed in `c0067f4`: `AbilityEffectDefinition.SubConditions` / `.SubEffects` / `.Costs` all carry `= new()` (`:7-9`), so no list on either ability SO class can be null. *Previous status line:* ✅ FIXED 2026-09-22 (owner, working tree, uncommitted) — operands swapped at `AbilityEffectDefinition.cs:26`; the copy at `AbilityDefinition.cs:67-75` deleted outright with its zero-caller method. No site remains. *Previous status line:* Open — CONFIRMED

## Description

`Assets/Script/System/Abilities/Core/AbilityEffectDefinition.cs:24-32`:

```csharp
protected virtual bool CheckPayCostValid(AbilityContext context)
{
    if (Costs.Count == 0 || Costs == null) return true;
```

`||` short-circuits left to right, so `Costs.Count` is evaluated **first**. If `Costs` is null the
`.Count` access throws `NullReferenceException` before the `Costs == null` operand is ever
evaluated. The guard is unreachable by construction; swapping the two operands is the entire fix.

### Related unguarded sites in the same subsystem

| File:line | Code | Guard |
|---|---|---|
| `AbilityEffectDefinition.cs:13` | `if (SubConditions.Count > 0)` | none — field declared at `:7` with no initializer |
| `AbilityInstance.cs:157` | `if (statCosts.Count == 0) return;` | no null test at all; called at `:85` with `effect.Costs` |

`AbilityInstance.TryPayEffectCost(effect.Costs)` (`:155-162`) is the live caller: it receives the
per-effect `Costs` list added in `73ab8e7` and indexes `.Count` with no guard whatsoever.

### Why it is latent rather than live

`AbilityDefinition.cs:25` declares:

```csharp
public List<StatCost> Costs;          // no  = new()
```

which is inconsistent with its two siblings on the same class:

```csharp
31:    public List<AbilityConditionDefinition> Conditions = new();
34:    public List<AbilityEffectDefinition> Effects = new();
```

`AbilityEffectDefinition.SubConditions` (`:7`), `SubEffects` (`:8`) and `Costs` (`:9`) likewise have
no initializers. Unity's serializer materialises an empty `List<T>` for every serialized list field
when it loads a `ScriptableObject` from disk, so every asset-authored instance arrives with a
non-null empty list and the guards never fire. Any instance created in code — `CreateInstance<T>()`
in a future EditMode test, a runtime-built definition, or a field added to an existing asset before
Unity re-serialises it — arrives with `null` and throws.

This is a correctness bug that is currently masked by a serializer implementation detail. It should
be fixed before the first EditMode test is written (see **BUG-084**), because that is the exact
context in which it stops being latent.

## Suggested Fix

1. Reverse the operands and use the null-conditional form:
   ```csharp
   if (Costs == null || Costs.Count == 0) return true;
   ```
2. Same at `AbilityEffectDefinition.cs:13` and `AbilityInstance.cs:157`.
3. Add `= new()` initializers to `AbilityDefinition.Costs` and to
   `AbilityEffectDefinition.SubConditions` / `.SubEffects` / `.Costs`, matching `Conditions` and
   `Effects`.

## FIXED — 2026-09-22 (owner, working tree, uncommitted)

Both sites are resolved, by two different means.

**Site 1 — `AbilityEffectDefinition.cs:26`, the original.** Operands swapped:

```diff
-        if (Costs.Count == 0 || Costs == null) return true;
+        if (Costs == null || Costs.Count == 0) return true;
```

The null test now runs first, and `||` short-circuits before `.Count` is reached, so a null `Costs`
returns `true` instead of throwing. This is the guard the original pretended to be.

**Site 2 — `AbilityDefinition.cs:67-75`, added in `2a83469`.** Deleted outright rather than fixed.
It had zero callers and its loop body was already inlined into `TryStart():60-63`, so nothing was
lost — and deleting it removed the copied defect along with the dead method. That also closes
BUG-091 item 3a in the same edit.

**Status: Open → FIXED.** No site remains. Not yet committed, not yet run.

## Re-verification — 2026-09-25 (HEAD `c0067f4`) — the residual named in the last entry is now FIXED

The 2026-09-22 entry closed the two null-check-after-dereference sites but recorded one site of the
same shape still open: `AbilityEffectDefinition.SubConditions` (`:7`) had no initialiser and was
dereferenced at `:13`.

`c0067f4` closed it, and the other two lists with it:

```diff
-    public List<AbilityConditionDefinition> SubConditions;
-    public List<AbilityEffectDefinition> SubEffects;
-    public List<StatCost> Costs;
+    public List<AbilityConditionDefinition> SubConditions = new();
+    public List<AbilityEffectDefinition> SubEffects = new();
+    public List<StatCost> Costs = new();
```

All three fields on `AbilityEffectDefinition` now carry `= new()`, so:

- `TryCast():13` — `SubConditions.Count > 0` can no longer meet a null
- `CheckPayCostValid():26` — already had the operands in the right order; the initialiser makes the
  null half of that test unreachable as well
- `AbilityInstance.PayCost():131-137` — `foreach (var statCost in statCosts)` had no list guard and
  is called with `effect.Costs` at `:75`. That is now safe too, as a side effect

Together with `AbilityDefinition.Costs = new()` / `.Conditions = new()` / `.Effects = new()`
(`AbilityDefinition.cs:25,31,34`, added 2026-09-22), **every list on both ability SO classes now has
an initialiser**. No remaining site of this defect class is known in the Abilities v2 core.

**Status**: unchanged — **FIXED**. This entry records that the last residual is gone, so the bug can
be closed without a follow-up.

The rule that came out of this bug still stands and still has an open instance elsewhere:
`Stat.modifiers` (**BUG-063**) is the same family of defect and is deliberately deferred.
