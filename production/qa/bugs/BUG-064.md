## Original Description (2026-08-30, superseded except item 7)

The entity-refactor session that CLAUDE.md's 2026-08-28 changelog credits with fixing
BUG-042/043/044/046/033/NEW-2 (deleting `EntityStatsSO.cs` and `EntityWeaponMelee.cs`, removing
`EntityFindTarget`, restructuring `Entity.cs`/`EntityData.cs`) left dangling references that fail to
compile:

1. `EntityData.cs:8` still declares a field of type `EntityStatsSO` — that type was deleted this week.
2. `Entity.cs` — the `EntityData data` field was removed, but `LoadEntity()`, `LoadState()`, and
   `SetDataEntity()` still reference `data`.
3. `Entity.Data` (the public getter) was removed, but is still called from `EntityInput.cs:81,83`,
   `EntityAttack.cs:68`, and `EntityEffectStats.cs:20`.
4. `EntityInput.cs:57,61` still references `EntityFindTarget`, deleted this week with no replacement —
   this is the same class CLAUDE.md's "Enemy targeting (NEW-1)" item already flagged as needing
   reimplementation; it is now a hard compile error, not just missing behavior.

**Even once compilation is restored**, source reading surfaced three further breaks that will fire the
moment an enemy dies or a ranged weapon is fired:

5. `EntityDeathState.cs:17` emits `ON_ENEMY_DEATH` with a `Vector3` position payload, but both
   subscribers — `EnemySpawner.ReleaseEnemy` and `ItemSpawner.DropItem` — cast the payload to
   `GameObject`. `InvalidCastException` on every enemy death.
6. `EnemySpawner.OnDisable()` calls `EventManager.Resgister` instead of `EventManager.UnResgister` for
   `ON_ENEMY_DEATH` — violates `.claude/rules/manager-event-code.md`'s register/unregister pairing rule;
   causes a duplicate live subscription on every enable/disable cycle.
7. `RangeWeapon.cs:7` declares `[SerializeField] private IObjecPoolService poolManager` with no
   `[Inject]` Construct method (unlike the correctly-migrated `EnemySpawner`/`ItemSpawner`). Unity
   cannot serialize an interface field via Inspector, so `poolManager` is always null — ranged combat
   silently never fires, no exception, no log.

## Impact

- **No Play Mode session, smoke check, or manual QA can run at all** until items 1-4 are fixed — this
  blocks S11-07 (Play Mode verify) and every other bug's true status from being confirmed this cycle.
- CLAUDE.md's 2026-08-28 claim that BUG-042/043/044/046/033/NEW-2 are "FIXED" is currently unverifiable
  against a running build — the fix commit landed the regression that breaks the build used to verify it.
- Items 5-7 mean that even after the build compiles again, the enemy-death chain and ranged combat are
  still broken — the demo's core loop (melee + ranged combat + enemy death + room clear) cannot complete
  end to end.
- No EditMode/PlayMode test exists (`tests/` dirs are `.gitkeep` only, TD-014) to catch a compile break
  like this before it reaches a shared branch — this is the first tracked case of a genuine build break
  landing on `sprint-11`.

## Suggested Fix

1. Restore or replace every dangling reference: either bring back a minimal `EntityData.StatsSO`-shaped
   field/property that points at the new `Entity.Stats`/`EntityStatsHandler` path, or update
   `EntityInput.cs`, `EntityAttack.cs`, and `EntityEffectStats.cs` to read from the new location directly.
2. Delete or reimplement `EntityFindTarget`-dependent code in `EntityInput.cs:57,61` — this is the same
   work NEW-1 already deferred; decide now rather than carrying a second cycle as a compile error.
3. Change `EntityDeathState.cs:17`'s `ON_ENEMY_DEATH` payload to `GameObject` (matching what
   `EnemySpawner`/`ItemSpawner` already expect), or update both subscribers to accept `Vector3` —
   pick one and make both ends agree.
4. Fix `EnemySpawner.OnDisable()`'s `Resgister` → `UnResgister` typo-in-logic (not the typo-in-name,
   which is intentional project convention — the *method choice* itself is wrong here).
5. Add `[Inject]` DI wiring to `RangeWeapon` for `IObjecPoolService`, matching the pattern already used
   in `EnemySpawner`/`ItemSpawner`, and drop the `[SerializeField]` on the interface field.
6. Recommend landing a compile-check pre-push hook (already tracked separately as the long-carried
   process-gate item) so a non-compiling commit cannot reach a shared sprint branch again.

Must be the first commit attempted in Sprint 12 — nothing else this cycle can be verified against a
running build until this lands.
