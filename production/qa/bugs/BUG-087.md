# BUG-087

**Title**: `ON_PLAYER_DEATH` has zero subscribers and no `GameManager` exists — player death is a permanent hard lock with no recovery path
**Severity**: S1 (the demo's stated life cycle "death/restart" cannot happen; the run is unrecoverable)
**Priority**: 1
**System**: Game life cycle / Event bus / Player
**Found by**: Documentation/source re-verification pass, 2026-09-22 (branch `main`, HEAD `d17fcc5`, merge of `e2cb75e`)
**Status**: Open — CONFIRMED

## Description

Project-wide search over `Assets/**/*.cs`:

```
$ grep -rn "ON_PLAYER_DEATH" Assets --include=*.cs
Assets/Script/Character/Player/States/PlayerDeathState.cs:18:   EventManager.Emit(EventID.ON_PLAYER_DEATH);
Assets/Script/Manager/EventManager.cs:42:                        ON_PLAYER_DEATH,

$ grep -rn "GameManager" Assets --include=*.cs | wc -l
0
```

Two hits total: one emitter, one enum declaration. **No `Resgister` call anywhere binds to it**, and
no `GameManager` class exists in the project at all.

The consequences chain:

1. The player enters `PlayerDeathState`, the death animation plays, `ON_PLAYER_DEATH` is emitted
   (repeatedly — see **BUG-086**).
2. Nothing listens. No scene reload, no restart prompt, no run teardown.
3. The player-side `VitalStatsComponent` has **no reset path**. `currentStats` is populated exactly
   once, in `Start()` (`VitalComponent.cs:19-24`), and the class has no `Reborn()` and no other
   writer that restores it. HP stays at 0.
4. `PlayerData.Reborn()` still has no caller, and `PlayerData.currentHealth` is still never written
   (the long-standing Bug #6 / story S10-08).
5. `ON_REALOAD_GAME` (`EventManager.cs:43`) has **zero emitters and zero subscribers** — the enum
   value that would carry a restart was declared and never wired.

Net effect: once the player dies, the only exit is quitting Play Mode. The demo target recorded in
`CLAUDE.md` — "start menu → dungeon run → death/restart" — has no implementation of its final third.

## The pattern to copy already exists on the enemy side

`EntityVitalStats` does what the player side does not:

| Line | Code |
|---|---|
| `EntityVitalStats.cs:31-35` | `public void Reborn() { Core.GetCoreComponent(out statHandler); currentStats = statHandler.GetFullStat(); }` |
| `EntityVitalStats.cs:23` | called from `Start()` |
| `EntityVitalStats.cs:26-29` | called from `OnEnable()` — so a pooled enemy re-spawns at full health |

`VitalStatsComponent` (player) has neither the method nor the `OnEnable()` hook.

## Suggested Fix

This is a feature-sized gap, not a one-liner. Minimum viable shape:

1. Add `VitalStatsComponent.Reborn()` mirroring `EntityVitalStats.cs:31-35`, and decide whether it
   is also called from `OnEnable()`.
2. Create a `GameManager` (scene component, registered in `GameLifetimeScope` — **not** a singleton,
   per `.claude/rules/manager-event-code.md`) that `Resgister`s `ON_PLAYER_DEATH` in `OnEnable()`
   and `UnResgister`s in `OnDisable()`.
3. On death: stop the run, show a restart affordance, then call `PlayerData.Reborn()` +
   `VitalStatsComponent.Reborn()` and either reload `StartScene` or emit `ON_REALOAD_GAME` and give
   that value its first subscriber.
4. Fix **BUG-086** first, or the handler will run at frame rate.

### What changed: the player inherited `Reborn()`

The ADR-0005 refactor moved the vitals into a shared base, and the reset the enemy side always had
now exists on the player too:

```csharp
// VitalStatsBase.cs
protected override void Start()
{
    base.Start();
    Reborn();                                          // :17
}

public virtual void Reborn()                           // :20
{
    if (statHandler == null) Core.TryGetCapability(out statHandler);
    currentStats = statHandler.GetFullStat();          // :23 — re-seeds every current stat to max
}
```

`VitalStatsComponent : VitalStatsBase<Core>` gets this for free. So the piece this bug described as
missing — *"player-side `VitalStatsComponent` has no `Reborn()`"* — **is now present**.

**Two gaps remain around it**, and they are what is left of this bug:

1. **Nothing calls it after `Start()`.** The enemy side adds `void OnEnable() { Reborn(); }`
   (`EntityVitalStats.cs:7-10`) because pooled enemies are re-enabled rather than re-instantiated.
   The player is never pooled, so `OnEnable` is not the right hook for it — a revive has to call
   `Reborn()` explicitly.
2. **There is still nobody to call it.** No `GameManager`, no `ON_PLAYER_DEATH` subscriber, no
   emitter for `ON_REALOAD_GAME`.

So death is still a **permanent hard lock**. The remaining work is smaller than it was: the reset
mechanism exists and only needs an owner and a trigger.

### Shape of the fix, unchanged

A `GameManager` as a **scene component registered in `GameLifetimeScope`**, not a singleton
(`.claude/rules/manager-event-code.md`), subscribing to `ON_PLAYER_DEATH` in `OnEnable()` and
unsubscribing in `OnDisable()`, calling `VitalStatsComponent.Reborn()` plus whatever movement
`Unlock` the death `Lock` from BUG-065 needs.

**Do not add the subscriber until BUG-086 is fixed** — the event currently fires every frame.

**Status**: unchanged — Open. Scope reduced: `Reborn()` no longer has to be written, only called.
