# BUG-078

**Title**: `SpawnSummonEffect.Casting()` returns its gate inverted and spawns the summon a second time in `Apply()`
**Severity**: S1 (logic — Paladin Consecrate spawns two summons and charges cost on the failure path)
**System**: Abilities v2 / Spawn effects
**Found by**: Manual code review of the Abilities v2 architecture, 2026-09-21 (`origin/feature/fix-player-control`, HEAD `15242e6`)
**Status**: Open

## Description

`Assets/Script/System/Abilities/Effects/SpawnSummonEffect.cs:20-25`:

```csharp
public override bool Casting(AbilityContext context)
{
    if (!base.Casting(context)) return true;
    base.Apply(context);
    return false;
}
```

Two problems:

1. **Inverted return.** `AbilityInstance.Casting()` treats a `true` return as "this effect fired, charge
   the cost" (see BUG-076). Here the *failure* branch — `base.Casting(context)` false, i.e. a
   `SubCondition` was not met — returns `true`, and the *success* branch returns `false`. So the cost is
   charged precisely when the effect did **not** run, and skipped when it did.

2. **Double spawn.** `Casting()` calls `base.Apply(context)` (the `SpawnEffectBase` projectile-style
   spawn, using `SpawnPos()`/`Angle()`), and then `AbilityInstance.TryDoInstant()` → `Execute()` calls
   the overridden `Apply(context)` (line 14), which spawns `summonPrefab` again through
   `context.Services.Pool.Spawn(...)`. A single Consecrate cast therefore instantiates two pooled
   objects, only one of which ever gets its `Launch(...)` callback wired the way `SummonExecute`
   expects.

   The two spawns are not even the same prefab: `base.Apply` spawns `SpawnEffectBase.Prefab`,
   the override spawns `SpawnSummonEffect.summonPrefab`.

Also in the override `Apply()` (line 16-18): `obj.GetComponent<SpawnSummonBase>()` is dereferenced with
no null check, unlike `base.Apply()` which guards and logs.

## Reproduction

1. Cast Paladin Consecrate in `LoadRandomMap`.
2. Observe two spawned objects (rune circle + lightning prefab) where one is expected.
3. Give the ability a `SubCondition` that fails; observe the Mana cost is still deducted.

## Suggested Fix

Settle what `Casting()` is for first (BUG-076 blocks this — the contract is undefined). Assuming
"return true when this effect consumed the cast":

```csharp
public override bool Casting(AbilityContext context)
{
    if (!base.Casting(context)) return false;
    Apply(context);
    return true;
}

public override void Apply(AbilityContext context)
{
    if (summonPrefab == null) return;
    var obj = context.Services.Pool.Spawn(summonPrefab.gameObject, context.TargetPoint, Quaternion.identity);
    if (obj.TryGetComponent<SpawnSummonBase>(out var controller))
        controller.Launch(Lifetime, context, SummonExecute);
}
```

and make sure `AbilityInstance` does not also call `Apply()` for an effect that already ran in `Casting()`.
