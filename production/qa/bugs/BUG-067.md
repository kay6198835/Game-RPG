# BUG-067

**Title**: `ResourceReceiver` heal and damage calls are swapped — picking up a healing item damages the player
**Severity**: S1 (shipped, reachable functional regression on the new Item pickup path)
**System**: Player / Vitals / Item
**Found by**: `pm-weekly-wrapup` code-review pass, 2026-09-13 (autonomous, `lead-programmer` agent via `/code-review`)
**Status**: Open

## Description

`Assets/Script/Character/Player/CoreComponent/ResourceReceiver.cs:17-24` has its two methods calling
the wrong `VitalStatsComponent` method:

```csharp
public void ReceverRecovery(StatType statType, float amount)
{
    vitalStatsComponent.ReceiveReduction(statType, amount);   // heal calls DAMAGE
}

public void ReceiveReduction(StatType statType, float amount)
{
    vitalStatsComponent.ReceiverRecovery(statType, amount);   // damage calls HEAL
}
```

This is not a theoretical path — `Assets/Script/System/Item/ItemEffectDefinition/RecoveryEffectDefinition.cs:13`
calls `resourceReceiver.ReceverRecovery(StatType.HP, amount)` when a player picks up a healing item.
Because the method bodies are swapped, that call reduces HP instead of restoring it. The new Item
pickup system (`853fe39`, `9f1258c`) and the `PlayerResourceReceiverState` added this sprint both
route through this exact entry point, so any healing consumable currently damages the player on pickup.

## Impact

- Direct, player-visible regression on the golden path of the new Item system: picking up a heal
  item hurts the player instead of healing them.
- No EditMode/PlayMode test exists to catch a swap like this (`tests/` — `.gitkeep` only, TD-014).

## Suggested Fix

Swap the two method bodies back: `ReceverRecovery` → `vitalStatsComponent.ReceiverRecovery(...)`,
`ReceiveReduction` → `vitalStatsComponent.ReceiveReduction(...)`. One-line-per-method fix; recommend
pairing with a first EditMode test asserting `ReceverRecovery` increases current HP and
`ReceiveReduction` decreases it, so this class of swap-bug can't regress silently.
