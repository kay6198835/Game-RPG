# BUG-066

**Title**: `EntityVitalStats` indexes `currentStats[statType]` with no key-existence guard — `KeyNotFoundException` risk on the enemy damage/heal chain
**Severity**: S2 (would throw on the live damage chain for any `StatType` missing from an entity's stat profile — not yet observed to fire, but the guard `ai-code.md`/`gameplay-code.md` require is absent)
**System**: Enemy AI / Damage Chain / StatSystem
**Found by**: `pm-weekly-wrapup` code-review pass, 2026-09-06 (autonomous, weekly wrap-up)
**Status**: Open — re-verified 2026-09-25 (HEAD `c0067f4`). **MERGED with BUG-070**: the ADR-0005 refactor moved the unguarded dictionary into the shared `VitalStatsBase.cs:28,39,41,45,52,54,58`, so the two bugs are now the same seven lines. One fix closes both. *Previous status line:* Open — CONFIRMED 2026-09-22. Same defect as BUG-070 (player side); fix and close together.

## Description

`Assets/Script/Character/Entity/CoreComponent/EntityVitalStats.cs` (new this sprint, part of the
BUG-053 fix) backs current HP/stat values with a plain `Dictionary<StatType, float>` populated once
from `statHandler.GetFullStat()` in `Reborn()`. Three public methods index it directly with no
existence check:

```csharp
public float GetCurrentStatValue(StatType statType) => currentStats[statType];

public void ReceiverRecovery(StatType statType, float amount)
{
    if (currentStats[statType] + amount >= statHandler.GetStatValue(statType)) ...
}

public void ReceiveReduction(StatType statType, float amount)
{
    if (currentStats[statType] - amount <= 0) ...
}
```

`ReceiveReduction` is called directly from `EntityNegativeReciver.TakeDamage()` — i.e. every hit on
every enemy runs through this indexer. If `statHandler.GetFullStat()` ever returns a dictionary that
does not include `StatType.HP` (or whatever `StatType` a caller passes — `WeaponHolder`/skills can
pass others), this throws `KeyNotFoundException` and the enemy's entire damage chain breaks for that
instance. `EntityData`/`BaseStatsSO`-driven profiles are data-authored (per
`scriptableobject-data.md`), so a minimal or misconfigured enemy profile is a realistic authoring
mistake, not a hypothetical.

## Impact

- `ai-code.md`'s Null Safety section requires null-checks before dereferencing entity data; this is
  the dictionary-key equivalent of that same class of risk, on the exact hot path (`TakeDamage`) the
  rule is meant to cover.
- No EditMode test exists for `EntityVitalStats` (per `tests/EditMode/` being `.gitkeep`-only,
  TD-014) that would catch this before it reaches a running enemy.

## Suggested Fix

Use `TryGetValue` (or `ContainsKey` + indexer) in all three methods, and either log + no-op or throw
a clear, named exception (`"EntityVitalStats: StatType.{x} missing from profile on {gameObject.name}"`)
instead of letting the raw `KeyNotFoundException` surface. Pairs well with `S12-11`'s planned first
EditMode test for the Entity damage chain — this is a natural first assertion to write (`ReceiveReduction`
on a StatType absent from the profile should not throw an unlabelled framework exception).

Neither file contains a single `TryGetValue` or `ContainsKey` call. The two classes are near-verbatim

### The player-side indexer is on the live death path

`PlayerBasicState.cs:74`

```csharp
if (vitalStats.GetCurrentStatValue(StatType.HP) <= 0)
```

runs every frame the take-damage flag is set, and goes straight to `VitalComponent.cs:28`.

### Two concrete ways this throws

**1. Initialisation-order race.** `currentStats` is populated only in `Start()`
(`VitalComponent.cs:19-24`). Unity does not guarantee `Start()` ordering between components, so any
component whose `Awake()`/`Start()` reads a vital value can run first and hit an empty dictionary.
The enemy side has a sharper version of this: `EntityVitalStats.OnEnable()` (`:26-29`) calls
`Reborn()`, and `OnEnable` runs **before** `Start()` — so on the first enable, `Reborn()`'s
`Core.GetCoreComponent(out statHandler)` (`:33`) may not resolve, and `statHandler.GetFullStat()`
(`:34`) throws or returns nothing.

**2. A `StatType` absent from the profile asset.** `BaseStatsSO.FullStatsValue()` (`:91-99`) adds
only the `StatType`s present in that SO's own stat list. Any `StatType` a designer did not author
into the asset is simply absent from the dictionary. That is not hypothetical: both
`HasEnoughManaCondition.IsMet()` (`HasEnoughManaCondition.cs:11`) and
`AbilityEffectDefinition.CheckPayCostValid()` (`:29`) look up
`Services.Vital.GetCurrentStatValue(cost.statType)` for a `StatType` chosen freely by whoever
authored the ability asset. Authoring an ability with a cost in a stat the character's profile does
not declare throws `KeyNotFoundException` at cast time.

### Fix (both files, one pass)

Replace every raw indexer with a guarded lookup. A shared helper is worth it precisely because the
duplication is what produced the second instance:

```csharp
private bool TryGet(StatType statType, out float value) => currentStats.TryGetValue(statType, out value);
```

and decide the miss policy once — return `0f`, or seed the key from the stat handler on demand. A
`KeyNotFoundException` from a dictionary the caller cannot see is the worst of the options.

Pair with the first EditMode test (TD-014) as sprint-14 S14-13 planned — but note that story is
blocked by **BUG-084** (no `.asmdef` anywhere, and `tests/` sits outside `Assets/`), so the test
cannot actually be written until that is resolved.

## Re-verification — 2026-09-25 (HEAD `c0067f4`) — STILL OPEN, and now the same file as BUG-070

The ADR-0005 refactor merged the enemy and player vitals into one shared base. `EntityVitalStats` is
now:

```csharp
public class EntityVitalStats : VitalStatsBase<EntityCore>
{
    private EntityStatsHandler entityStatsHandler;
    private IMovement movement;

    void OnEnable() { Reborn(); }                            // :7-10

    public override void Reborn()                            // :12
    {
        if (entityStatsHandler == null) Core.GetCoreComponent(out entityStatsHandler);
        entityStatsHandler.ResetRuntimeModifiers();
        if (movement == null) Core.TryGetCapability(out movement);
        movement?.ClearImpacts();
        base.Reborn();
    }
}
```

The dictionary this bug is about moved to `Assets/Script/Character/Base/VitalStatsBase.cs`, which the
player also derives from (`VitalStatsComponent : VitalStatsBase<Core>`). **BUG-066 and BUG-070 are
therefore no longer two instances of one defect — they are literally the same seven lines.** Fix
once, close both.

`currentStats[statType]` is still indexed with no key guard, at:

| Line | Member |
|---|---|
| `:28` | `GetCurrentStatValue` — **on the live death path**, read by `PlayerBasicState` |
| `:39`, `:41`, `:45` | `Recovery` |
| `:52`, `:54`, `:58` | `Reduction` |

`currentStats` is filled by `Reborn()` (`:20-24`) from `statHandler.GetFullStat()`, so any
`StatType` that stat profile does not seed throws `KeyNotFoundException` on first read.
