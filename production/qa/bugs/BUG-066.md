# BUG-066

**Title**: `EntityVitalStats` indexes `currentStats[statType]` with no key-existence guard — `KeyNotFoundException` risk on the enemy damage/heal chain
**Severity**: S2 (would throw on the live damage chain for any `StatType` missing from an entity's stat profile — not yet observed to fire, but the guard `ai-code.md`/`gameplay-code.md` require is absent)
**System**: Enemy AI / Damage Chain / StatSystem
**Found by**: `pm-weekly-wrapup` code-review pass, 2026-09-06 (autonomous, weekly wrap-up)
**Status**: Open

## Description

`Assets/Script/Character/Entity/CoreComponent/EntityVitalStats.cs` (new this sprint, part of the
BUG-053 fix) backs current HP/stat values with a plain `Dictionary<StatType, float>` populated once
from `statHandler.GetFullStat()` in `Reborn()`. Three public methods index it directly with no
existence check:

```csharp
public float GetCurrentStatValue(StatType statType) => currentStats[statType];

public void ReceiverRecovery(StatType statType, float amount)
{
    if (currentStats[statType] + amount >= statHandler.GetStatValue(statType)) ...
}

public void ReceiveReduction(StatType statType, float amount)
{
    if (currentStats[statType] - amount <= 0) ...
}
```

`ReceiveReduction` is called directly from `EntityNegativeReciver.TakeDamage()` — i.e. every hit on
every enemy runs through this indexer. If `statHandler.GetFullStat()` ever returns a dictionary that
does not include `StatType.HP` (or whatever `StatType` a caller passes — `WeaponHolder`/skills can
pass others), this throws `KeyNotFoundException` and the enemy's entire damage chain breaks for that
instance. `EntityData`/`BaseStatsSO`-driven profiles are data-authored (per
`scriptableobject-data.md`), so a minimal or misconfigured enemy profile is a realistic authoring
mistake, not a hypothetical.

## Impact

- `ai-code.md`'s Null Safety section requires null-checks before dereferencing entity data; this is
  the dictionary-key equivalent of that same class of risk, on the exact hot path (`TakeDamage`) the
  rule is meant to cover.
- No EditMode test exists for `EntityVitalStats` (per `tests/EditMode/` being `.gitkeep`-only,
  TD-014) that would catch this before it reaches a running enemy.

## Suggested Fix

Use `TryGetValue` (or `ContainsKey` + indexer) in all three methods, and either log + no-op or throw
a clear, named exception (`"EntityVitalStats: StatType.{x} missing from profile on {gameObject.name}"`)
instead of letting the raw `KeyNotFoundException` surface. Pairs well with `S12-11`'s planned first
EditMode test for the Entity damage chain — this is a natural first assertion to write (`ReceiveReduction`
on a StatType absent from the profile should not throw an unlabelled framework exception).
