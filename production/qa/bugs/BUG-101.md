# BUG-101

**Title**: Bug-ID collision — `CLAUDE.md` uses BUG-093/094/095 for three defects that differ from `production/qa/bugs/BUG-093..095.md`
**Severity**: S3 (documentation drift; three real defects have no bug file and cannot be triaged)
**Priority**: 2
**System**: Process / documentation (`CLAUDE.md`, `/doc-sync`, bug register)
**Found by**: Project review, 2026-10-08 (branch `sprint-17`, HEAD `1b24ef7b`)
**Status**: Open

## Description

The 2026-10-05 doc sync (`7d1b5c79`) added three rows to the `CLAUDE.md` Known Bugs table and header:

| ID in `CLAUDE.md` | Defect described there |
|---|---|
| BUG-093 | `RangeWeapon.nextFireTime` written, never read — `RangeAttackSO.RecoveryTime` has no effect |
| BUG-094 | `PlayerState.Enter()` logs every state change without an editor guard |
| BUG-095 | `AttackSO.attackDamege` → `attackDamage` rename without `[FormerlySerializedAs]`; `SnS_State1-3.asset` lose 55 stage damage |

The bug files with those IDs, created 2026-09-28 by the weekly wrap-up, describe different defects:

| File | Title |
|---|---|
| `BUG-093.md` | `SpawnEffectBase` no longer reads `context.Forward` — projectile abilities always fire right |
| `BUG-094.md` | `RangeWeapon` rotates the character root on every attack |
| `BUG-095.md` | `Arrow.prefab` has no projectile script or collider |

Consequences:

- The three `CLAUDE.md` defects exist in no bug file, so `/bug-triage` never sees them.
- Any session reading `CLAUDE.md` and a triage report gets contradictory meanings for the same ID.
- `.claude/rules/scriptableobject-data.md` and `.claude/skills/doc-sync/SKILL.md` cite "BUG-095" for the
  `attackDamege` lesson, propagating the wrong ID.

Root cause: no single ID authority. `/doc-sync` allocated IDs without reading `production/qa/bugs/`;
`/bug-report` prescribes a 4-digit `BUG-[NNNN]` format the project does not use.

## Fix direction (not applied)

1. File the three `CLAUDE.md` defects as new bug files with the next free IDs (re-verify each at HEAD first).
2. Rewrite the three `CLAUDE.md` rows and the two rule/skill citations to the new IDs.
3. Adopt the ID rule in `production/review-flow.md` §2.4 / §9 #2 in every skill that writes bug IDs.
