# BUG-096

**Title**: Rooms with no `Tile_Spawn_Enemy` marker never open their doors — the player is locked in (fix `40d2c79` reverted by `ac13ee4`)
**Severity**: S1 (run cannot progress past the first such room; no error, only a `LogWarning`)
**Priority**: 1 (blocks the dungeon loop and the S16-07 / S17 Play Mode smoke)
**System**: Map / Room progression
**Found by**: Weekly wrap-up code review, 2026-10-05 (branch `sprint-16`, HEAD `ac13ee4`)
**Status**: ⚠️ Open — static analysis; needs one Play Mode confirmation

## Description

`RoomGeneraterController.LoadRoom()` (`:134-139`) treats every un-cleared room as a combat room:
it swaps the unused doors to walls, emits `ON_GET_SPAWN_POSITIONS` and waits for `ON_CLEAR_ENEMY` to
call `DeleteDoorTileMap()`.

`EnemySpawner.OnGetSpawnPositions()` (`:42-45`) returns early when the spawn list is empty, so
`ON_DONE_SPAWN_ENEMY` is never emitted, `RoomCell.EnemyCount` never reaches the `== 0` branch through
a death, and `ON_CLEAR_ENEMY` never fires. `RoomCell.IsCleared` has exactly one writer
(`RoomCell.cs:61`, inside that branch).

Five of the twenty rooms registered in `Maze_Storage.asset` this week have **zero** spawn markers:
`StartRoom_Entrance`, `BossRoom_ThroneArena`, `BuffRoom_PowerShrine`, `RestRoom_Campfire`,
`ShopRoom_Merchant` (grep of `Tile_Spawn_Enemy` in `Assets/Data/Json/Room/*.json`).

## History

- `40d2c79` (2026-10-04, Claude session) added a `spawnPositions.Count == 0` branch that builds the
  pathfinding grid and calls `DeleteDoorTileMap()` immediately.
- `ac13ee4` "done load map." (2026-10-04, owner) removed that branch again, together with scene and

## Consequence

Combined with BUG-097 (start cell receives the Boss room, which has no markers), the **first room of
every run** is expected to stay sealed. Any Buff / Rest / Shop room picked by
`Utility.PickUniqueIndex` locks the run the same way.

rooms)? If not, restore the `40d2c79` branch. If yes, record the intended rule here.
