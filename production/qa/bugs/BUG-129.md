# BUG-129

**Title**: Champion confirm does nothing — `19540dff` moved the confirm callback into `ConfirnData.callback`, but `UIEvents.OnOpenConfirmPanel()` ignores its `callback` argument and `PedestalChampionController` never sets the field, so the start room never opens
**Severity**: S1 (the run cannot leave the start room: no character data, no `ON_OPEN_DOOR`)
**Priority**: 1 (one line; blocks the whole demo loop after the menu)
**System**: UIFlow (confirm panel) / Start room (Champion monument)
**Found by**: weekly wrap-up 2026-11-20, review of the week's `.cs` (inbox note NOTE-20261120-7), STATIC at `sprint-23` `0069a40c`
**Status**: FIXED in code (`be973605`, 2026-11-21) — confirmed by automated Play Mode (QA-PLY-05 "Confirm applies the class" PASS for Paladin / Archer / Mage in runs `20261121-2050` and `20261121-2106`); awaiting a hand check (smoke step A3). Was: Open, confirmed by reading code (2026-11-20 triage)
**Fixed in**: `be973605`

## Description

`19540dff` "knockback, update UI confirm" (2026-11-20) removed `UIEvents.ConfirnRequest` /
`AccessAction()` and made `ConfirnPanel.AccessConfirm()` run `data.callback` instead:

- `Assets/Script/UIFlow/Gameplay/Windows/ConfirnPanel.cs:19-30` — `SetConfirm()` stores
  `data.callback`; `AccessConfirm()` calls `callback?.Invoke()`.
- `Assets/Script/UIFlow/Core/UIEvents.cs:71-74` — `OnOpenConfirmPanel(Action callback, ConfirnData data)`
  raises `OpenConfirnPanel.Invoke(data)` and drops `callback` (before, it stored it in `ConfirnRequest`).
- `Assets/Script/System/RoomGameSystem/PedestalChampionController.cs:32-36` — passes `SetCharacterData`
  as `callback` and builds `ConfirnData` with only `confirmText` / `cancelText`.

So `data.callback` is null, pressing Confirm only closes the panel, `SetCharacterData()` never runs:
the player keeps the unarmed base data and `ON_OPEN_DOOR` is never emitted, so the start room stays
sealed (smoke step A3 / A7).

Same method, older defect (BUG-102): `OpenConfirnPanel.Invoke(data)` is still unguarded (R3.6) and
`ResetStatics()` still does not clear `OpenConfirnPanel`.

## Fix direction (owner)

In `UIEvents.OnOpenConfirmPanel()`: `data.callback = callback; OpenConfirnPanel?.Invoke(data);`
(or drop the parameter and set `callback` in `PedestalChampionController`).

## How to verify

Play Mode from `MainGamePlay`: interact with a Champion monument, press Confirm — the class changes,
the start-room doors open. QA-PLY flow cases that confirm a class should PASS in the next automated run.

## Fix (2026-11-21 triage)

`be973605` "coding need check": `UIEvents.OnOpenConfirmPanel(ConfirnData data)` drops the unused
`callback` parameter (`UIEvents.cs:71-74`), and `PedestalChampionController.cs:32-37` sets
`callback = SetCharacterData` inside `ConfirnData`; `ConfirnPanel.cs:23,28` stores and runs it.
Re-read at `sprint-23` `68631d3f`. The unguarded `OpenConfirnPanel.Invoke(data)` (`UIEvents.cs:73`)
is still there — tracked by BUG-102, not this bug.
