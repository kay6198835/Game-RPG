# BUG-119

**Title**: `VitalStatsBase.Recovery()` adds without clamping — a heal pushes current HP / Mana above max
**Severity**: S3 (gameplay value wrong; no error)
**Priority**: 3 (fold into the stat-reduction epic with BUG-113)
**System**: Character / Stats (`VitalStatsBase`)
**Found by**: weekly wrap-up code review 2026-10-31 (NOTE-20261031-3) at `sprint-20` `2276049e`
**Status**: Open — confirmed by reading code; not yet observed in Play Mode
**Fixed in**: —

## Description

`Assets/Script/Character/Base/VitalStatsBase.cs:64-71`: if `current < max` it does
`current += amount` with no upper bound; only when `current` is already at or above max is it reset to
max. HP 95 / 100 + heal 10 → 105. The overshoot persists until the next damage. The previous version
of this method clamped (see BUG-113's description); the clamp was lost in `786c031b` / `6e484f0c`.

`max` here is still `statHandler.GetStatValue()` = `AdjustedValue` (BUG-113), so even a correct clamp
ignores gear / buff modifiers until BUG-113 is fixed. `Reduction()` (`:77`) still indexes
`currentStats` unguarded (BUG-066/070).

## Expected fix (owner)

`currentStats[t] = Mathf.Min(currentStats[t] + amount, max)` with `max` read from `FinalValue`
(BUG-113).

BUG-113, BUG-066 / BUG-070, BUG-117.
