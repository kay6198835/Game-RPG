# BUG-131

**Title**: `Interact.FindNearestObject()` walks the whole 3-slot `colliders` buffer instead of the first `numFound` entries — a stale collider from an earlier search can be picked and interacted with again
**Severity**: S3 (double pickup / interacting with an object already released to the pool; no crash seen)
**Priority**: 2 (one-line loop bound)
**System**: Player core components (interaction) / Items
**Found by**: coverage review session 2026-11-20 (inbox note NOTE-20261120-6); confirmed by the 2026-11-20 wrap-up triage, STATIC at `sprint-23` `0069a40c`
**Status**: Open — confirmed by reading code; not observed at runtime (new Play Mode case QA-ITEM-12 targets it)
**Fixed in**: —

## Description

`Assets/Script/Character/Player/CoreComponent/Interact.cs:34` fills `colliders` with
`Physics2D.OverlapCircleNonAlloc(...)`, which writes only the first `numFound` slots and leaves later
slots untouched. `FindNearestObject()` (`:54-71`) iterates `foreach (Collider2D collider in colliders)`
and stops only at a null slot, so after one search that found two or three objects, a later search
that finds one still compares the leftover slots — for example an item already collected and
returned to the pool — and may return it as "nearest".

Also in the same method: "nearest" is measured to `playerInputHandler.MouseVector`, not to the player.
Confirm with the owner whether that is intended (aim-to-pick).

## Fix direction (owner)

`for (int i = 0; i < numFound; i++)` over `colliders[i]`.

## How to verify

QA-ITEM-12 (two items in reach, two Q presses) PASS; by hand: drop two items close together, pick both
up, then press Q again near one remaining object — only live objects react.
