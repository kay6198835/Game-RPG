# BUG-097

**Title**: Bug #16 is now live — `Maze_Storage.asset` is alphabetical, so the start cell gets the Boss room and the end cell gets the Start room
**Severity**: S2 (wrong room at both ends of every run; no error)
**Priority**: 1 (same fix window as BUG-096)
**System**: Map / Room generation
**Found by**: Weekly wrap-up code review, 2026-10-05 (branch `sprint-16`, HEAD `ac13ee4`)
**Status**: ⚠️ Open — static analysis
**Supersedes**: historical Bug #16 (CLAUDE.md Known Bugs) — that bug was latent; this is its manifestation

## Description

`RoomGeneraterController.Setting()` (`:55-56`) forces
`room[_startIndex] = full.room[0]` and `room[_endIndex] = full.room[Count - 1]`. `RoomType` is never
read.

`d3400ee` / `ac13ee4` (2026-10-04) rebuilt `Maze_Storage.asset` with 20 rooms in **alphabetical**
order (`:17-74`):

- `room[0]` = `BossRoom_ThroneArena.json`
- `room[19]` = `StartRoom_Entrance.json`

So the start cell loads the Boss arena and the end cell loads the entrance.

Secondary: `Utility.PickUniqueIndex(totalCount, pickCount)` draws from all 20 entries, including the
Boss and Start rooms, so either can also appear in the middle of the maze.

## Fix

Preferred (closes Bug #16 for good): select start/end/boss by `RoomType` and exclude those types from
the random pool. Stop-gap: reorder `Maze_Storage.asset` so Start is first and Boss is last.

## Verify

Play Mode: the first room is `StartRoom_Entrance`, the end cell is `BossRoom_ThroneArena`, and neither
appears anywhere else in the maze across several seeds.

## Re-verification — 2026-10-09 (HEAD `221d54be`, project review run 2)

Still open; `Maze_Storage.asset` unchanged since `ac13ee4f` (first entry `BossRoom_ThroneArena`, last
`StartRoom_Entrance`); `RoomGeneraterController.cs:55-56` unchanged.

**The bug is now load-bearing.** The champion-select monuments (`Tile_Spawn_Champion_Monument_{Paladin,
Archer,Mage}`) exist only in `Assets/Data/Json/Room/BossRoom_ThroneArena.json` — the file this bug loads
at the start cell. Confirming a champion emits `ON_OPEN_DOOR` (`ChampitionController.cs:40-44`), which is
what opens the first room today. Fixing this bug by `RoomType` as written above would move champion
select to the end of the run and load `StartRoom_Entrance` (no spawn marker, no champion) first, where
BUG-096 locks the player in.

**Decide first** which JSON is the start room; move the champion tiles there; then fix this bug and
BUG-096 in the same change. Updated Verify: the first room shows the three monuments and its doors open
after a champion is confirmed.
