# BUG-074

**Title**: `StatsEffectBase.Apply` feeds the *current* vital value into `Utility.ModifierStatsCalculate`, then uses the result as the recovery/reduction *amount*
**Severity**: S3 (balance/logic)
**System**: Abilities v2 / Stat effects
**Found by**: `pm-weekly-wrapup` code-review pass, 2026-09-19 (autonomous)
**Status**: Open — CONFIRMED 2026-09-22 (arithmetic verified from source; design intent for the sign convention still unclear, no GDD). No partial fix in flight — see re-verification.

## Description

`StatEffectBase.cs:26-30`: `impactValue = ModifierStatsCalculate(mods, currentVital)`; that value is passed
to `Recovery(...)` / `Reduction(...)`. With a `PercentAdd 0.2` modifier the result is `current * 1.2`, so a
"heal 20%" effect heals 120% of current HP (clamped to max) and a "deal 20%" reduction removes 120% of
current. Flat +10 gives `current + 10`, not 10. Almost certainly the *delta* (`result - current`) was intended.
Also: the file is `StatEffectBase.cs` but the class is `StatsEffectBase`.

## Suggested Fix

Confirm intent in a design note; likely `impactValue = result - currentStatVital`.

### The defect, with the arithmetic spelled out

`Assets/Script/System/Abilities/Effects/StatEffectBase.cs:23-30` (class `StatsEffectBase` — the
file/class name mismatch is intentional and documented in `CLAUDE.md`):

```csharp
23: foreach (var kvp in grouped)
25:     StatType currentStatTypeKey = kvp.Key;
26:     float currentStatVital = context.Services.Vital.GetCurrentStatValue(currentStatTypeKey);
27:     float impactValue = Utility.ModifierStatsCalculate(kvp.Value, currentStatVital);
29:     ApplyImpact(context, currentStatTypeKey, impactValue);
```

`Utility.ModifierStatsCalculate(List<StatModifier>, float baseValue)`
(`Assets/Script/Utility/Utility.cs:274-304`) takes the base value, transforms it in place across the
`Flat` / `PercentAdd` / `PercentMult` branches, and `return baseValue;` (`:303`) — i.e. it returns
the **post-modifier total**, which is what its name promises.

That total is then handed to `ApplyImpact` as the parameter named `impactValue`, and downstream
treated as an *amount to add or subtract*:

- `RecoveryReductionPerTimeForDuration.cs:14` → `Vital.RecoveryPerTimeForDuration(statType, impactValue, ...)`
- `RecoveryReductionPerTimeForDuration.cs:17` → `Vital.ReductionPerTimeForDuration(statType, impactValue, ...)`
- and ultimately `VitalComponent.cs:46` → `currentStats[statType] += amount;`

Worked example: current HP = 100, one `PercentAdd +0.10` modifier.
`ModifierStatsCalculate` returns `110`. `ApplyImpact` heals **110**, not **10** — an 11× error.
On the `Reduction` side it is worse in kind, not just degree: a debuff authored as "drain 10%"
subtracts 90 from a 100-HP pool, because it passes `90` (the remaining total) as the amount to
remove.

### (a) `ModifierStatsCalculate` has exactly one caller — the contract is safe to change

```
$ grep -rn "ModifierStatsCalculate" Assets --include=*.cs
Assets/Script/System/Abilities/Effects/StatEffectBase.cs:27
Assets/Script/Utility/Utility.cs:274        (the declaration)
```

One call site in the whole project. The stat system proper (`BaseStatsSO`, `Stat`,
`DerivedStatFormula`) does **not** route through this helper — it has its own layered
`FinalValue` computation. So there is no risk of breaking stat calculation by changing either the
helper or its call site.

### (b) The fix belongs at the call site, not in the helper

`ModifierStatsCalculate` returns a total, and its name says so. Changing it to return a delta would
make the name a lie for any future caller. Do the subtraction where the meaning is known:

```csharp
float currentStatVital = context.Services.Vital.GetCurrentStatValue(currentStatTypeKey);
float total = Utility.ModifierStatsCalculate(kvp.Value, currentStatVital);
float delta = total - currentStatVital;
ApplyImpact(context, currentStatTypeKey, delta);
```

Also consider `Mathf.Abs(delta)` or a signed contract for `ApplyImpact`: today the `Recovery` /
`Reduction` direction comes from the `impactType` enum (`StatEffectBase.cs:7`), so a negative delta
combined with `StatImpactType.Reduction` would heal. That sign convention needs writing down — it is
part of the same open design question (demo-checklist item 21).
