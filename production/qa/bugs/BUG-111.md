# BUG-111

**Title**: `RegenComponent` fails as soon as it is wired — `_cacheDatas` never initialised, `KeyNotFoundException` on any non-HP/Mana stat change, regen never re-enabled after damage
**Severity**: S3 (dormant today: no caller of `Regenning()`)
**Priority**: 3 (fix before the component is put on a prefab)
**System**: Character / Stats (regen)
**Found by**: `/daily-standup --auto` 2026-10-20 (NOTE-20261020-3) + session stat-system review 2026-10-21; confirmed by weekly wrap-up triage 2026-10-25 at `sprint-19` `05dcf630`
**Status**: Open — confirmed by reading code (dormant)
**Fixed in**: —

## Description

`Assets/Script/Character/Player/CoreComponent/RegenComponent.cs` (added `3d768b3d`, build-fixed
`ddb1d702` / `8a36bc3e`):

1. `public Dictionary<StatType, RegenData> _cacheDatas;` (`:8`) has no initialiser; `SeedRegenData()`
   calls `_cacheDatas.Add(...)` (`:53`, `:61`) → `NullReferenceException` on first use (a public
   dictionary is not serialized by Unity, so the Inspector does not create it either).
2. `OnChangeStatMax(StatType)` indexes `_cacheDatas[statType]` (`:33`, `:39`) for every
   `BaseStatsSO.OnStatChanged`, which fires for all 17 stat types → `KeyNotFoundException` on a
   STR / DEX / … change (one stat point).
3. The class derives from `MovementBase<Core>`, not a core-component base.
4. `SetData()` subscribes `OnChangeStatMax` once per cache entry (2×).
5. `StatHandler.ResignChangeStat()` / `ClearResignChangeStat()` (`StatHandler.cs:34-43`) use the raw
   `statsSO` field, which is null when the profile comes from `PlayerData` (`ResolveProfile()` fallback,
   `:21`) → NRE, including in `OnDisable()`. Use `StatsSO`.
6. Cached `currentValue` starts at max and is refreshed only after a regen tick, and the gate is
   `currentValue == maxValue` (float equality), so taking damage never re-enables regen; HPRegen /
   ManaRegen changes are never picked up.
7. Max is read through `GetStatValue()` (= `AdjustedValue`) — see BUG-113.

`OnChangeStatMax()` (no parameter, from `IRegenResource`) is a `throw new NotImplementedException()`
stub since `8a36bc3e`.

## Expected fix (owner)

Initialise the dictionary, ignore stat types it does not track (`TryGetValue`), subscribe once, use
`StatsSO`, read current values from `IVitalComponent` on each tick instead of caching them.

## How to verify

Put `RegenComponent` on the player prefab, spend one stat point (no exception), take damage, wait —
HP must regenerate up to max.
