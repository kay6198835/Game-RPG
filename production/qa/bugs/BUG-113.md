# BUG-113

**Title**: "Max stat" has two meanings — `BaseStatsSO.GetStatValue()` returns `AdjustedValue` (no equipment, no modifiers) while vitals are seeded from `FinalValue`, so a heal can lower HP and Defense buffs are ignored
**Severity**: S2 (wrong combat numbers whenever gear or buffs are active)
**Priority**: 2 (stat-reduction epic, story-002)
**System**: Stats / Vitals
**Found by**: session stat-system review 2026-10-21 (NOTE-20261021-1); confirmed by weekly wrap-up triage 2026-10-25 at `sprint-19` `05dcf630`
**Status**: Open — confirmed by reading code; not yet observed in Play Mode
**Fixed in**: —

## Description

- `Assets/Script/System/StatSystem/BaseStatsSO.cs:194-197` — `GetStatValue()` returns
  `stat.AdjustedValue` = `baseValue + levelUpValue` (`:359`).
- `:96` — `FullStatsValue()` returns `stat.FinalValue` = `baseValue + levelUpValue + equipmentValue`
  (`:361`).
- `Assets/Script/Character/Base/VitalStatsBase.cs:26` — `Reborn()` seeds `currentStats` from
  `GetFullStat()` (FinalValue).
- `:54-56` — `Recovery()` clamps to `statHandler.GetStatValue()` (AdjustedValue).

With +20 HP gear (max 120): current 115 + heal 10 is clamped to **100** — a heal lowers HP. The same
un-buffed max is read by the enemy Defense reduction (`EntityNegativeReciver.cs:30`), the enemy HP-bar
ratio (`:25`, can exceed 100%), the HUD max HP / Mana (`RealPlayerDataProvider.cs:153-154`), the
`GetCurrentStatValue()` missing-key fallback (`VitalStatsBase.cs:42`) and `RegenComponent` (BUG-111).

Planned fix: `production/epics/stat-reduction/story-002-one-max-definition.md`.

## Expected fix (owner)

`GetStatValue()` returns `FinalValue`; add a separately named accessor if an un-buffed value is ever
needed.

## How to verify

Equip gear with +HP, take a small hit, heal — HP must rise, never drop; HUD max must include the gear.
