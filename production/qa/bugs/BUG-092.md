# BUG-092

**Title**: `RecoveryReductionPerTimeForDuration` does not compile — `perTime` was deleted but is still used
**Severity**: S1 (BUILD — `Assembly-CSharp` fails; no Play Mode, no Test Runner, no verification of any other bug)
**Priority**: 1
**System**: Abilities v2 / Effects
**Found by**: Post-fetch source re-verification, 2026-09-25 (branch `origin/feature/fix-player-control`, HEAD `c0067f4` "fixing")
**Status**: ⚠️ Open — CONFIRMED by direct read of source and of the commit that introduced it

## Description

Commit `c0067f4` deleted the field `public float perTime;` from
`Assets/Script/System/Abilities/Effects/RecoveryReductionPerTimeForDuration.cs` but left the two call
sites that read it. There is no `perTime` declared anywhere reachable from that class.

The diff, in full:

```diff
-    public float duration;
-    public float perTime;
+    private float duration;
+    [Range(1, 10)]
+    private int timeCount;
     protected override void ApplyImpact(IVitalComponent vital, StatType statType, float impactValue)
     {
         switch (impactType)
         {
             case StatImpactType.Recovery:
-                vital.RecoveryPerTimeForDuration(statType, impactValue, perTime, duration);
+                vital.RecoveryPerTimeForDuration(statType, impactValue, perTime, timeCount);
                 break;
             case StatImpactType.Reduction:
-                vital.ReductionPerTimeForDuration(statType, impactValue, perTime, duration);
+                vital.ReductionPerTimeForDuration(statType, impactValue, perTime, timeCount);
                 break;
         }
     }
```

## Evidence

`RecoveryReductionPerTimeForDuration.cs` at HEAD `c0067f4`, in full:

```csharp
public class RecoveryReductionPerTimeForDuration : StatsEffectBase
{
    private float duration;              // :6  — now unused
    [Range(1, 10)]
    private int timeCount;               // :8  — private, NOT serialized
    protected override void ApplyImpact(IVitalComponent vital, StatType statType, float impactValue)
    {
        switch (impactType)
        {
            case StatImpactType.Recovery:
                vital.RecoveryPerTimeForDuration(statType, impactValue, perTime, timeCount);   // :14
                break;
            case StatImpactType.Reduction:
                vital.ReductionPerTimeForDuration(statType, impactValue, perTime, timeCount);  // :17
                break;
        }
    }
}
```

`grep -rn "perTime" Assets --include=*.cs` returns **13 lines and not one declaration** visible to
this class. Every hit is either a *parameter* name in another type or one of the two broken uses:

| File | What the hit is |
|---|---|
| `VitalStatsBase.cs:64,66,69,71,74,80,81,85,91,92` | method **parameters** of `VitalStatsBase<TCore>`, out of scope here |
| `IVitalComponent.cs:13,14` | **parameter** names in the interface signature, out of scope here |
| `RecoveryReductionPerTimeForDuration.cs:14,17` | **the two broken uses** |

The base classes do not declare it either: `StatsEffectBase` (`StatEffectBase.cs:6-8`) has
`statModifier`, `impactType`, `recipient`; `AbilityEffectDefinition` (`:6-9`) has `AbilityName`,
`SubConditions`, `SubEffects`, `Costs`.

**Expected compiler output**: `error CS0103: The name 'perTime' does not exist in the current context`
at lines 14 and 17.

## Impact

Same class of blocker as BUG-088 was on 2026-09-22: `Assembly-CSharp` does not build, so there is no
Play Mode, no Test Runner, and **no bug in this register can be verified in the Editor until it is
fixed**. It is the first thing to fix.

## Second defect in the same file — do not close this bug without it

Even once `perTime` is restored, the effect still will not work as authored:

`timeCount` (`:8`) is `private` with **no `[SerializeField]`**, so Unity does not serialize it and
the designer cannot set it in the Inspector. `[Range(1, 10)]` on a non-serialized field is inert —
it draws nothing, because there is no drawn field. The value is therefore `0` on every asset.

Follow that `0` through `VitalStatsBase` at HEAD:

```csharp
public void RecoveryPerTimeForDuration(StatType statType, float amount, float perTime, float timeCount)
{
    StartCoroutine(RecoveryPerTime(statType, amount, perTime, timeCount));   // :71
}

IEnumerator RecoveryPerTime(StatType statType, float amount, float perTime, float timeCount)
{
    Recovery(statType, amount);   // :76 — fires once
    timeCount--;                  // :77 — 0 becomes -1
    if (timeCount > 0)            // :78 — false
    {
        yield return new WaitForSeconds(perTime);
        RecoveryPerTimeForDuration(statType, amount, perTime, timeCount);
    }
}
```

So a HoT/DoT asset degenerates into **exactly one instant tick** — indistinguishable at runtime from
`RecoveryReductionStatsEffect`, and silent about it.

`duration` (`:6`) is now private and read by nothing: `warning CS0169: The field
'RecoveryReductionPerTimeForDuration.duration' is never used`. Delete it or serialize it.

## Fix

1. Restore the field and serialize both, so the designer can author them:
   ```csharp
   [SerializeField] private float perTime = 0.5f;
   [Range(1, 10)]
   [SerializeField] private int timeCount = 1;
   ```
2. Delete `duration` (`:6`) — nothing reads it since `c0067f4` changed the fourth argument from a
   duration in seconds to a tick count.
3. After the build is green, set `perTime` and `timeCount` on any asset of this type before judging
   the effect. **Verify with an HP value changing more than once, not with a clean Console** — a
   `timeCount` of `0` produces a single silent tick and no error.
