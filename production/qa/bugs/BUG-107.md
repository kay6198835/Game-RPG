# BUG-107

**Title**: `WeaponHolderBase.EquipDefaultWeapon()` nulls `weapon` before releasing it — guaranteed `NullReferenceException` on any re-equip; also throws when `CharacterData.Weapon` is unset (Mage)
**Severity**: S2 (exception on the Champion confirm path; the old weapon leaks)
**Priority**: 1 (two-line reorder plus one guard)
**System**: Character / Weapons
**Found by**: `/daily-standup --auto` 2026-10-19 (NOTE-20261019-1); confirmed by weekly wrap-up triage 2026-10-19 at `sprint-18` `0def62ab`
**Status**: Open — confirmed by reading code and asset YAML; not yet observed in Play Mode
**Fixed in**: —

## Description

`Assets/Script/Character/Base/WeaponHolderBase.cs:45-54` at `0def62ab` (from `cae75317`):

```csharp
if (weapon != null)
{
    weapon = null;
    objectPoolManager.Release(weapon.gameObject);   // weapon is null here
}
GameObject instance = objectPoolManager.Spawn(Core.Data?.Weapon.gameObject, OwnerTransform.position, Quaternion.identity);
instance.GetComponent<Weapon>().Equid(this);
```

1. When a weapon is already equipped (second Champion pick, any future re-equip) the release line
   dereferences the field it just cleared → `NullReferenceException`, and the old weapon instance is
   never returned to the pool.
2. `Core.Data?.Weapon.gameObject` guards only `Data`. `Assets/SO/Player/Mage/Mage.asset` has no
   `<Weapon>k__BackingField` (only a stale `defaultWeapon: {fileID: 0}`), and `BaseData.asset` stores
   `{fileID: 0}`, so picking the Mage throws here. The previous "no prefab → return" guard was
   removed in the same commit.
3. `Equid()` → `Equid_UnEquid()` toggles: called while `this.weapon` is still set it would *unequip*.
   Today the null-before-release order hides that, but a naive swap of the two lines changes it.

Only caller: `Player.SetCharacterData()` (`Player.cs:89`). Relates to BUG-106.

## Expected fix (owner)

Release first, then clear the field, then return early when `Data == null || Data.Weapon == null`.
Author a weapon on `Mage.asset` (or make "unarmed" an explicit, guarded case).

## How to verify

Play Mode: confirm one Champion, then interact with a second one and confirm — no exception, the old
weapon disappears, the new one swings. Pick the Mage — no exception.
