# BUG-075

**Title**: `SpawnProjectileBase` uses the 3D `OnTriggerEnter(Collider)` signature in a 2D project — projectile abilities never register a hit
**Severity**: S1 (shipped, reachable functional break — every projectile-type ability deals zero damage)
**Priority**: 1
**System**: Abilities v2 / Spawn effects
**Found by**: Manual code review of the Abilities v2 architecture, 2026-09-21 (`origin/feature/fix-player-control`, HEAD `15242e6`)
**Status**: Open

## Description

`Assets/Script/System/Abilities/Runtime/SpawnMono/SpawnProjectileBase.cs:29` declares:

```csharp
private void OnTriggerEnter(Collider other)
```

The class is `[RequireComponent(typeof(Rigidbody2D))]` + `[RequireComponent(typeof(CircleCollider2D))]`
and `Awake()` sets `_col.isTrigger = true`. Unity dispatches 2D trigger events **only** to
`OnTriggerEnter2D(Collider2D)`; the 3D `OnTriggerEnter(Collider)` callback is never invoked for a
`Collider2D`/`Rigidbody2D` pair. The method therefore never runs, so:

- `_context.Services.NegativeReceiver` is never assigned from the projectile path
- `_callback.Invoke(_context)` never fires, so `SpawnProjectileEffect.Execute()` never calls
  `TakeDamage(...)`
- the projectile flies until its `Lifetime` coroutine releases it back to the pool

Affects `SlashProjectile` (Paladin Blessed Slash) and any future `SpawnProjectileBase` subclass.
The only other trigger handler in the repo, `DoorController.cs:19`, correctly uses
`OnTriggerEnter2D(Collider2D)`.

This also compounds BUG-072: the shared `Services.NegativeReceiver` field the summon path reads is
written *only* here, so it is permanently null on a fresh run.

## Reproduction

1. Equip an `AbilityDefinition` whose `Effects` contain a `SpawnProjectileEffect`.
2. Cast it so the projectile passes through an enemy collider.
3. Observe: no damage applied, enemy health bar unchanged, projectile despawns on `Lifetime`.

## Suggested Fix

```csharp
private void OnTriggerEnter2D(Collider2D other)
```

and null-guard the callback before invoking:

```csharp
if (!other.TryGetComponent<INegativeReceiver>(out var receiver)) return;
_context.Services.NegativeReceiver = receiver;
_callback?.Invoke(_context);
```

Longer term the receiver should be passed as a callback argument rather than stashed on the shared
`AbilityServices` instance — see BUG-072.

### Why this bug is invisible — record this, it has already caused a false dismissal

This defect produces **no compile error, no compile warning, and no Console output**:

- `UnityEngine.Collider` (the 3D type) exists in every Unity project, including a pure-2D one — the
  physics module is always present. So `OnTriggerEnter(Collider)` is a perfectly valid method
  signature and compiles clean.
- Unity dispatches trigger messages by matching method name. A `Collider2D` + `Rigidbody2D` pair
  dispatches `OnTriggerEnter2D`; it does not fall back to `OnTriggerEnter`.
- Unity does not warn about a message-named method that nothing will ever call.

The result is a method that looks correct, compiles correctly, and is simply never invoked. During a
prior review this bug was assumed not to exist on the grounds that "it would have errored" — it does
not error. Anyone re-checking should confirm by adding a `Debug.Log` inside the method rather than
by reading the Console.

### Blast radius is wider than this file states

The method is not only the projectile's hit handler — line 32 is the **only** writer of
`_context.Services.NegativeReceiver` in the entire repository. Because it never runs, that field is
permanently null, and the summon path reads it too. See **BUG-072**, where this is now recorded in
full: at HEAD, *no* Abilities v2 effect deals damage, not just projectile ones.
