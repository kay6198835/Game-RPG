# BUG-104

**Title**: `PlayerState.Enter()` logs `"Enter State: " + animBoolName` on every player state change, unguarded — string concat + log shipped in builds
**Severity**: S4 (cost and Console noise, no gameplay effect)
**Priority**: 4 (delete or wrap in `#if UNITY_EDITOR`)
**System**: Character / Player state machine
**Found by**: `/doc-sync --auto` 2026-10-09 (NOTE-20261009-11, one of the three unfiled defects listed in BUG-101); confirmed by weekly wrap-up triage 2026-10-10 at `sprint-18` HEAD `c6cbc57a`
**Status**: Open — confirmed by reading code
**Fixed in**: —

## Description

`Assets/Script/Character/Player/PlayerState.cs:34` (inside `Enter()`, `:28-36`):

```csharp
Debug.Log("Enter State: " + animBoolName);
```

No `#if UNITY_EDITOR` guard. Every state change allocates a string and writes a log line, in the Editor
and in a Player build. The player changes state many times per second in combat (attack chains, take
damage, idle/move), so the Console is flooded during a playtest and real warnings are buried.
`.claude/rules/ai-code.md` / `gameplay-code.md` allow state-change logging only behind
`#if UNITY_EDITOR` and forbid string concatenation in hot paths.

Added in `9154763f` (2026-09-30). It was mislabelled "BUG-094" in `CLAUDE.md` on 2026-10-05 (BUG-101).

Related: NOTE-20261009-2 (an NRE logged at this line from an uncommitted version of the file; not
reproduced in either Editor session of 2026-10-10).
