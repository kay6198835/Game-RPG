# BUG-065

**Title**: `PlayerDeathState` no longer stops `PlayerMovement` — CLAUDE.md's BUG-044 "FIXED" claim is stale against current source
**Severity**: S2 (player can keep sliding/moving during the death animation — wrong behaviour, not a crash)
**System**: Player / State Machine
**Found by**: `pm-weekly-wrapup` code-review pass, 2026-09-06 (autonomous, weekly wrap-up)
**Status**: Open

## Description

CLAUDE.md's Known Bugs table (BUG-044) states:

> ✅ FIXED — `PlayerDeathState` now instantiated in `Player.Awake()` and properly stops
> `PlayerMovement` (not `EntityMovement`) in `Enter()`

Current `Assets/Script/Character/Player/States/PlayerDeathState.cs` (verified against `sprint-12`
HEAD `f3f5f08`):

```csharp
public class PlayerDeathState : PlayerDisadvantageState
{
    public PlayerDeathState(Player player, string animBoolName) : base(player, animBoolName) { }
    public override void Enter()
    {
        base.Enter();
    }
    public override void LogicUpdate()
    {
        if (Status == StatusAnimation.EndRangeTrigger)
        {
            EventManager.Emit(EventID.ON_PLAYER_DEATH);
        }
    }
}
```

`Enter()` only calls `base.Enter()`, which (`PlayerDisadvantageState.Enter()`) does
`player.Core.GetCoreComponent(out inputHandler)` — nothing else. No call to `PlayerMovement.Stop()`
(or equivalent) exists anywhere in `PlayerDeathState.cs` or its base class. The construction fix
(`Player.Awake()` now builds the state) is correct and still holds, but the movement-stop half of
the original BUG-044 fix is gone — either reverted in a merge, or the claim in CLAUDE.md was already
inaccurate at the time it was written (this cycle did not investigate the file's git history to
determine which).

## Impact

- The player can continue moving during the death animation/state, which reads as a broken death
  sequence (sliding corpse) rather than a clean stop.
- CLAUDE.md's Known Bugs table cannot be trusted at face value for this entry — another instance of
  the "doc updated ahead of / disconnected from verified source" pattern already flagged by BUG-052
  and the Sprint 11 retro for BUG-053.

## Suggested Fix

Resolve `PlayerMovement` via `Core.GetCoreComponent` in `PlayerDeathState.Enter()` (after
`base.Enter()`) and call its stop/zero-velocity method, matching the pattern CLAUDE.md already
describes as intended. Re-run `/doc-sync` afterward so the Known Bugs table matches verified source
again.

## Re-verification — 2026-09-25 (HEAD `c0067f4`) — STILL OPEN, but the fix is now a one-liner

`PlayerDeathState` is unchanged:

```csharp
public override void Enter()      // :10
{
    base.Enter();                 // :12 — and nothing else
}
```

**What changed is the tooling around it.** ADR-0005 Amendment 2 added `IMovement`
(`Assets/Script/Interface/IMovement.cs`), the movement of one character as seen by systems that
impact it:

```csharp
public interface IMovement
{
    Vector2 Velocity { get; }
    bool CanMove { get; }                                  // false while locked or knocked back
    float SpeedMultiplier { get; }
    void SetVelocity(Vector2 velocity);
    void Stop();                                           // :17
    void AddSpeedMultiplier(object source, float multiplier);
    void RemoveSpeedMultiplier(object source);
    void Lock(object source);                              // :20
    void Unlock(object source);
    void ApplyKnockback(Vector2 velocity, float duration);
    void ClearImpacts();
}
```

Before this existed, "stop PlayerMovement on death" meant reaching for a concrete component from a
state class. Now it is `Core.TryGetCapability(out IMovement movement)` then `movement.Lock(this)`.

**Use `Lock(source)`, not `Stop()`.** `Stop()` zeroes the velocity for one call; the next
`PhysicsUpdate` writes it again. `Lock(source)` sets `CanMove` false and holds it, which is the
durable state a death needs. `.claude/rules/weapon-skill-code.md` requires that every `Lock` is
paired with an `Unlock` by the same `source` — for death that pairing belongs in whatever revives
the player, which does not exist yet (**BUG-087**), so note the debt when adding it.

**Status**: unchanged — Open. Effort revised down: one resolve plus one call in `Enter()`.

Do not fix this in isolation. `PlayerDeathState.LogicUpdate()` emits `ON_PLAYER_DEATH` every frame
(**BUG-086**) and nothing subscribes to it (**BUG-087**). Order: BUG-086, then this, then BUG-087.

Not verified in Play Mode — the project does not compile at this HEAD (**BUG-092**).
