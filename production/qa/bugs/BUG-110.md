# BUG-110

**Title**: Player weapon drop / floor pickup never updates `WeaponHolderBase.weapon` and never injects the picked-up weapon — a dropped weapon keeps attacking, a picked-up one is ignored (and a ranged one can never fire)
**Severity**: S2 (weapon swap broken; no exception, silent)
**Priority**: 2 (restore the holder bookkeeping that `3d768b3d` removed)
**System**: Character / Weapons
**Found by**: `/daily-standup --auto` 2026-10-20 (NOTE-20261020-2, second half); fix-survival PARTIAL on BUG-064 (2026-10-25); confirmed by weekly wrap-up triage 2026-10-25 at `sprint-19` `05dcf630`
**Status**: Open — confirmed by reading code; not yet observed in Play Mode
**Fixed in**: —

## Description

`3d768b3d` ("add regen system", 2026-10-19) removed `WeaponHolderBase.Equid_UnEquid()` and its calls
from `Weapon.Equid()` / `UnEquid()`. Only `EquipDefaultWeapon()` (`WeaponHolderBase.cs:45-56`) still
writes the holder's `weapon` field and injects the instance (`:53-54`, fixed in `05dcf630`).

The floor path in `Assets/Script/Character/Player/CoreComponent/WeaponHolder.cs` does neither:

- **Drop** (`Intertion()`, `:47-50`): calls `weapon.UnEquid(this)` and returns. `Weapon.UnEquid()`
  (`Weapon.cs:102-115`) unparents the weapon and clears its own `holder`, but the holder's `weapon` field
  is never set to null. `CanAttack()` / `Attack()` / `MakeDamage()` keep driving the weapon lying on the
  floor; the next `Intertion()` drops it again instead of picking anything up.
- **Pickup** (`:52-55`): `groundWeapon.Equid(this)` parents the weapon and applies its stat modifiers,
  but `this.weapon` is never assigned, so the player attacks with whatever the field still holds (or
  nothing). `IObjectResolver.InjectGameObject()` is never called, so a picked-up `RangeWeapon` keeps
  `_objectPoolService == null` and `CanAttack()` (`RangeWeapon.cs:22-24`) returns false forever — the
  BUG-064 sub-item 7 symptom, back for this path only.
- `WeaponHolder.Start()` (`:28-31`) also calls `weapon.Equid(this)` on a `Weapon` found on the holder's
  own GameObject without storing it.

`WeaponHolder.GetWeapon(Weapon)` (`:81-86`, "Need check and fix this logic late") would store it, but has
no caller.

Relates to BUG-064 (sub-item 7), BUG-106, BUG-107.

## Expected fix (owner)

Route every equip / unequip through the holder: on pickup set `weapon`, inject the GameObject, then
`Equid()`; on drop call `UnEquid()` then set `weapon = null`.

## How to verify

Play Mode: drop the weapon (F near nothing) — LMB must do nothing. Pick up a ranged weapon from the
floor — it must fire and hit. Pick the melee weapon back up — it must swing at the player's position.
